## Operating rules
Mobile interface: GitHub Issues tasks/status, Actions job console,
PRs and reviews, CI artifacts. No additional paid platform is required.

Before EVERY train/eval, except the narrowly governed
`synthetic_diagnostic_fit` category specified below:
1. Authenticate real publisher dataset, causal observation times, original
   entity IDs, license, split and independently observed outcomes.
2. Freeze family, seeds, 100k +/-5% parameter target, matched competitors
   within 1%, equal original data and training budget, replayable checkpoint
   and PNDS mathematical obligations.
3. Add reviewed JSON study proposal under research/phone_queue and run the
   source-controlled phone_lab.py plan. Save the decision in the issue.
4. Route CPU/no-fit/source-only to GitHub Actions and justified CUDA/accelerated
   training to Kaggle. Kaggle must request NvidiaTeslaT4 (exactly T4 x2);
   fail if unavailable. Physically verify both and actually use both via
   independent frozen seed-shards or compatible two-rank DDP.
5. A compute decision does NOT permit training, spending GPU quota, or
   opening TEST. Scientific and independent signed real-source, reward,
   goal and ACL preflight evidence must pass. Independent evaluator private
   keys are never given to an agent or model process.
6. Keep phone-visible stages: proposed, sourced, planned, blocked, awaiting
   approval, submitted, running, measured, replay, qualified or failed.
   Preserve failures and replay evidence. Do not silently train, merge or
   claim real-world improvement from fabricated fixture tests.

## Agent roles
Researcher: original hypothesis and evidence plan.
Engineer: smallest reviewed change and safe compute.
Reviewer: separate source integrity, anti-cheat, real outcomes and replay.
Lab manager: compute routing, approvals, Issue progress and status.

Custom GitHub coding-agent instructions are provided, not a silently
installed paid continuous coding-agent runtime. Any connected coding agent
must follow these rules and leave novel-model PRs draft.


## Narrow synthetic diagnostic-fit route (2026-11-03)

Read `research/SYNTHETIC-DIAGNOSTIC-FIT-EXCEPTION-2026-11-03.md` for the sole
new `synthetic_diagnostic_fit` category. Scope approval does not approve
unseen implementation bytes or a run. This is an exploratory, single-seed,
100k-scale, within-1%-parameter, matched-exposure mechanism screen, never an
architecture ranking/selection, qualification or promotion. Existing no-fit
diagnostics, authentic real-source and full-comparison/signed paths stay
unchanged. Full fixed budgets and no rescue tuning are mandatory; CPU time
need not match.

Only this category may use reviewed bounded local CPU execution instead of
the general phone-queue/planner and Actions routing. Require a new canonical
registration, externally verified root scope approval, independent exact
source review and a separate one-shot bounded release before numerical
work. Source-only CI consistency cannot authorize a run. Preserve historical
bytes, actual counts, checkpoints, receipts, failures and PNDS obligations.
No TEST, real corpus, private checkpoint, GPU, paid compute, publication or
merge permission is created.
