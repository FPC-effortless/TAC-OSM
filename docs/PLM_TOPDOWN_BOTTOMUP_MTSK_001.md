# PLM Top-Down Assembly / Bottom-Up Ablation — MTSK-001

Status: preregistered. No confirmatory result was present when this protocol was registered.

## Scientific method

This lane applies the repository's general method:

**Top-down assembly:** construct a complete end-to-end decision loop using standard/scaffold components and exactly one novel architectural block.

**Bottom-up ablation:** remove or simplify properties of that block one at a time while keeping the surrounding model, benchmark, training schedule, parameter budget, and evaluation procedure fixed.

The tested top-down loop is:

environment
-> observation
-> persistent state update/read
-> relevance router
-> structural executor
-> action
-> environment outcome
-> verifier
-> next state boundary

Only the persistent-state representation is novel: **Multi-Timescale Adaptive State Kernel (MTSK).**

The router is a conventional tanh MLP. The executor has fixed action semantics. The verifier is an independent environment-result check. No LLM, external teacher, hidden evaluator state, or task-specific answer encoding enters the router input.

## Benchmark

Each episode contains a length-H observation history followed by a decision with current observation exactly zero.

The correct action is determined by a hidden temporal contrast:

- fast state trace versus slow state trace;
- fast versus medium;
- medium versus slow.

The hidden pair of temporal scales is not exposed to the model.

For every evaluation pair, one history is paired with its negation. Therefore:

- the current observation is identical;
- the optimal actions are opposite;
- the two histories differ only in their prior observations.

This makes current-input-only success exactly insufficient for the paired task.

Train and test use disjoint deterministic RNG streams. Class balance is constructed before measurement. Gold labels are used only as training targets and post-action verifier truth; they do not enter the state update or router features.

## Top-down model

All trained arms use the same policy:

current observation + three persistent state slots
-> 12-unit tanh hidden layer
-> two-action logits.

Parameter count is identical across no-state, single-timescale, two-timescale and MTSK arms.

State slots always number three:

- no-state: all zeros;
- single-timescale: the same decay is repeated across all slots;
- two-timescale: two distinct decays with one repeated slot;
- MTSK: three logarithmically separated decays.

MTSK uses fixed decays (0.50, 0.90, 0.98). The benchmark's ground-truth temporal filters are nearby but not identical (0.45, 0.88, 0.985), so the experiment tests approximation rather than copying exact generator constants.

## Bottom-up controls

The four trained representations form the primary reduction ladder:

no state -> one timescale -> two timescales -> three timescales.

After the MTSK policy is trained, two intervention tests reuse the frozen checkpoint:

- **reset:** replace the final state by zeros before action selection;
- **shuffle:** replace each final state by a state generated by another evaluation episode.

These are causal interventions, not retraining arms.

A load-bearing state mechanism should show a preregistered reduction in performance when its information is removed or replaced.

## Compute accounting

Per observation, one state trace update costs three arithmetic operations per state slot:
alpha*s + (1-alpha)*x.

The router uses the same fixed matrix dimensions for every trained arm. Verification is a separate counted operation.

Training compute is reported independently from evaluation compute. No claim is made from evaluation work while silently excluding training or state construction.

## Scientific boundaries

The primary hypothesis is a finite mechanism question. A positive result would not establish:

- biological equivalence to bacteria;
- scale-free/asymptotic memory;
- language, vision or audio capability;
- general intelligence;
- hardware speedup;
- superiority to Transformers, SSMs or other architecture families.

A negative result closes only the registered MTSK intervention on this benchmark.

## Required bottom-up successor after MTSK-001

Regardless of the result, the next experiment must remain registered:

1. if MTSK wins: vary scale spacing and learned-versus-fixed decays without changing the task;
2. if MTSK ties single-timescale: test whether the bottleneck is timescale representation or router capacity;
3. if reset/shuffle does not damage capability: inspect for current-input or benchmark leakage before interpreting any MTSK gain.

The universal G0-G10/P0-P7 protocol remains mandatory.
