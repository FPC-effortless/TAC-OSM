# Test6 scientific integration protocol proposal

Status: design proposal, not a registered completed capability experiment.
Freeze a new executable protocol before outcomes. Preserve DEV-029/031's
existing protocol and failures; larger evaluation and revised numerical
handling require a separately versioned study, provisionally DEV-033.

The question is whether the complete architecture improves predictive
retention and action utility after credible optimization, and what each
component contributes. Neither finite tuning nor a successful audit proves
an optimal learning ceiling or an unassailable scientific baseline.

## Component contracts and controls

| Component | Contract | Required comparisons |
|---|---|---|
| TAC/PLM | Persistent public-event state | Native, masked-local, schema41, tuned GRU/delta, explicit event table plus learned head; deterministic rules separately as oracle |
| CDL | Query-dependent relevance routing | Learned router, matched-k random/uniform selector, dense attention; exact NLL teacher separately if feasible |
| CASM | Selected structural computation | Neural operator bank versus trained parameter/compute-accounted MLP; original Boolean graph executor as a distinct implementation |
| OSM | Action-conditioned future dynamics | Planner on/off, prediction calibration and state-transition loss; identical action availability |
| Verifier | Post-action acceptance/correctness estimate from allowed receipts | Learned gate versus always-commit and matched-budget alternatives |
| Repair | Bounded subsequent action after feedback | On/off with every extra action, inspection and service charged |

Do not silently equate graph CASM, neural ConditionalExecutor and fusion
specialist pools. Supply an explicit adapter for masked-local memory before
calling that implementation integrated. Record module calls and causal
dependencies: routing must affect selected computation, computation and OSM
must affect action logits, and repair must execute an environment action.
Original CDL teacher replication is separate from cheap-router validation.

Run two distinct comparisons: frozen inference ablations diagnose dependence
of a trained model; matched retraining tests what alternative systems can
learn. Equalize tuning trial budgets and report parameters, measured training
time, inference latency, memory, active operations and total search cost.
Matched state size alone is insufficient. Single-component ablations do not
prove synergy. Any synergy claim requires prospectively selected factorial
interactions, with difference-in-differences and uncertainty, not merely a
full-system score greater than one ablation.

## Optimization and failures

First complete or formally supersede the blocked tuning comparison. Retain
all registered arms, budgets216/648/2160, learning-rate and curriculum trials,
and failed slots. Select only with validation. Check learning curves and
stability; a still-improving curve is evidence for further work, not proof of
an architectural limit. Investigate the GRU exception before changing its
numerics. A repaired recipe starts a new registered cohort; it cannot replace
the frozen failed cell or inherit a misleading success status.

The current selector requires the full matrix: a missing/failed cell does not
authorize silently choosing among survivors. Any prospective replacement
failure policy must record complete/failed statuses, include numerical
failures as failures for joint reliability gates, and report conditional
accuracy with its survivorship limitation. Do not fabricate zero accuracy
for an unevaluated model; state conservative bounds where appropriate.

## Larger evaluation and confirmation

Proposal: retain three delays, four roles, three deadline placements and two
paired partners. Increase repetitions from2 to16 for validation:1152 total,
768 mature all-role primary cases and384 cancellation cases per history and
initialization. Independently generate64 repetitions for untouched test:
4608 total,3072 mature primary,1536 cancellation. These counts require a new
generator interface and audit; the existing runner still uses2 repetitions.
Do not generate or inspect scientific test outcomes during development.

Freeze selected recipes, then run at least20 fresh initialization seeds per
arm on identical paired evaluation worlds. This is a planned reliability
sample, not a guarantee of statistical power. Report mean, median, standard
deviation, IQR, worst observed seed, and fraction passing every registered
gate, including training failures. Bootstrap paired differences over seeds
for95% intervals; if generalizing over worlds too, use a preregistered nested
resampling scheme respecting shared paired episodes. Do not treat thousands
of correlated events as independent training replications. Prespecify primary
contrasts and multiplicity handling before testing multiple ablations.

Primary: registered mature all-role predictive metric. Cancellation remains
a diagnostic: at48 cases, one outcome moves accuracy2.08 percentage points,
two move it4.17. The historical DEV-023 development result and DEV-024 failed
fresh replication remain distinct ledger entries.

Report absolute failures, unnecessary services, inspections, intervention
costs, model-only and selected costs, and paired uncertainty. Preserve exact
registered pass/fail thresholds while explaining the practical magnitude of
tiny cost differences. Perfect accuracy and zero observed failures are
bounded observations, not universal guarantees. Larger independent tests and
fresh seeds complement rather than replace physical-cost accounting.

## Task scope and audit

Keep supplied entity IDs and known future rules explicit. Discovery claims
require a separate identifiable indirect-cue task with permutation, unseen
entity and capacity tests; eight-way fixed slots do not test discovery.
Full integration must eventually evaluate all relevant entities, not only
the public target of DEV-032's engineering harness. Reuse the complete physical
simulator and charge repair without resetting elapsed time or costs.

Independent audit must verify source/checkpoint/protocol hashes, disjoint
namespaces, all registered successes and failures, predictions/actions,
receipt replay, physical costs, and selection without test access. Integrity
success establishes recorded execution, not scientific superiority.
