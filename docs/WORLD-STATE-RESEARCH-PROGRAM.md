# TAC-OSM learned world-state research program

Status: active development program, not a claim that the four phases are complete.
This implements the user's four-phase roadmap with explicit evidence boundaries.
DEV-059 remains a bounded fixed-training-budget comparison: its full agent beat
the matched GRU under that recipe, not all optimized recurrent models. CASM's
incremental contribution, convergence and robust training remain unestablished.
MTSK-specific superiority pursuit stays retired under DEV-056's deadline.

## Non-negotiable interpretation

A learned deployment policy may consume public records, candidate descriptions
and task descriptions. No teacher, entity-state dictionary, known-law transition
solver, cost argmin, retry rule or scripted completion controller may make its
runtime decisions. Simulator laws, protocol parsers, tensor architecture and
independent outcome checks are necessarily programmed infrastructure, listed
separately. A learned component with an imposed prior must name that prior.

In repository terminology CDL-style reads route evidence; neural CASM composes
operators. Temporal memory retrieval is not a redefinition of CASM as a memory
bank, nor evidence for general symbolic program discovery or original CDL
teacher distillation.

Finite experiments cannot prove perfect probability calibration, universally
zero faults or convergence to a global optimum. Use proper scoring losses,
held-out calibration curves, seed/world uncertainty and explicit failure bounds.
The verifier can establish outcomes in its operational simulator, not guarantee
real-world safety. A calibrated model can still face irreducible uncertainty.

The requested strict gate of better completion **and** lower cost than a public
script remains binding for an architectural superiority claim. A reference at
100% completion makes strict completion superiority impossible on that task.
Such a task can test functionality, learning and execution efficiency; it cannot
support that superiority claim. Do not weaken the gate or hide the ceiling.
Likewise an exact, unbounded Bayes-optimal reference cannot be beaten in expected
utility under its own assumptions. Use declared model misspecification, scale or
compute limits with strong adaptive controls when testing unique learned value.

## Phase 1 — stable clean-state control

1. **Temporal retrieval.** Compare a timestamp-aware learned content scorer,
   monotone temporal bias and a separately identified exact latest-record
   reference. Both learned scorers must see identical information. A strict
   newest-record mask is a programmed clean-record reference and must not enter
   the deployed learner without being disclosed as an imposed rule. Under noisy
   sensors, a new record does not automatically invalidate older evidence.
2. **Calibrated beliefs and costly errors.** Train completion/outcomes with
   unweighted proper scores. Train decision utility separately with the true
   asymmetric cost of unfinished work and delayed action. Cost-weighting a
   probability target changes the estimated probability and must not be called
   calibration. Keep learned stop separate from external task verification.
3. **Sparse execution.** Skip address/encoder work when the learned admission
   closes; verify exact behavior before measuring latency and allocation. Every
   observation still pays admission and ingestion costs. Count bank clones,
   resident state and actual executed tensor rows. Hardware DRAM bytes require
   hardware counters; allocator bytes and logical writes are different quantities.
4. **Whole-agent gate still required.** Ten fresh full-policy seeds, all curves,
   fixed budgets or preregistered budget escalation, an untouched test and the
   strongest public/adaptive controls. A plateau is not proof of convergence.
   Set minimum completion per entity/history family and a physical-fault guard
   before fitting. Zero stale-caused post-completion actions is an acceptance
   target to test with interventions, not a consequence of positive decay.

DEV-060 foundations implements sparse inference and an isolated ten-seed
retrieval probe. It does **not** retrain or promote a new whole-agent recipe.
A failed retrieval/agent gate remains a failure even if inference becomes faster.

## Phase 2 — uncertain information and paid acquisition

First verify the small finite-state environment before scaling its state space.
The executable foundation has two entities, 50% missing initial statuses, 10%
status errors, exact paid inspections and continuous per-world eight-dimensional
identities. Repair receipts always report both entities; their shape and identity
set cannot leak which hidden entity changed. Inspection provenance is public.

An exact four-state joint posterior is the information-matched reference.
Its receding-horizon expected-cost controller has declared depth two; it is not
a global oracle. The private safe-progress teacher is reported separately.
Public-minus-private cost includes both extra information and bounded planner
error. It is not a pure irreducible information gap. A private policy's action
choice can itself leak hidden information, so an interventional public filter
must not be advertised as a calibrated posterior conditional on those choices.

Before **learned policy training**, freeze a separate protocol with ten fresh
seeds per full/no-CASM/GRU/attention arm, identical public payloads and supervision,
matched resource budgets, calibration split, source hashes and stopping rules.
First establish minimum useful reference headroom. Report missing/premature stop,
physical repair, fault counts, inspections, actions and cost components. Derive
fixed-query belief calibration as well as visited-state diagnostics. Include a
public-history nonidentifiability fixture and a private-state access/import audit.

Diagnose separately:

- Information: public belief reference versus private teacher, with planner error
  and finite compute explicitly included.
- Representation: learned belief predictions versus exact public posteriors on
  the **same fixed public histories**.
- Decision: learned actions versus stronger public planning using the same belief,
  with diagnostic access confined to the evaluator.

Only after the small harness is verified, add N=4/6/8, longer dependency chains,
missing relations, new identities and repair-law drift as separate held-out
families. Preregister and charge observation, index-building, write/read and
planning compute. Full memory-bank scoring is not C5 learned indexed acquisition.
The original larger DEV-060 policy proposal remains a draft.

## Phase 3 — representation learning and reduced scaffolding

A JEPA-inspired experimental arm may predict an EMA target encoder's future
**public** representation from current public history plus an action embedding.
Record target construction, stopping gradients and variance/covariance or another
collapse check. The target must not quietly receive hidden fault labels.

The joint objective has separately logged prediction, action, decision and
retention terms. Freeze coefficients and resource accounting before outcomes.
Do not compare a pretrained TAC arm to an unpretrained baseline while calling
that an architectural advantage. Use retrained equal-budget no-CASM, standard
attention, GRU and representation-pretraining controls. Retention must be charged
and tested by future decision damage, not a noise-label base rate alone.

Remove task-specific feature assumptions incrementally, with an inventory of
public schema, generic identity handling, learned allocation and remaining
external constraints at every stage. Neural operator selection is not autonomous
symbolic program discovery. Claim the latter only with an explicit program
language, novel held-out programs, execution traces and appropriate controls.
No JEPA training or new symbolic discovery is claimed by DEV-060 foundations.

## Phase 4 — task interfaces and commercial evidence

Add text-described tasks/candidate choices only after versioning the encoder,
training corpus and deployment cost. A text adapter does not itself establish
world-state reasoning. Typed multi-question heads should reuse one state update
and expose evidence/uncertainty without claiming independent outcomes from a
shared representation. Test multiple judgments against separate forward passes.

Before Woyengi/Jev/LLM comparisons, identify exact repositories/versions, export
one common task and public-information contract, and freeze adapter permissions,
action/inspection budgets, provider/model versions and real billing caps. Do not
invent missing task sets or results. Account for encoder, model, retrieval, tool,
verification, acquisition and maintenance costs. Separate a simulator verifier
from real deployment outcome observability and monitoring.

The commercial gate requires held-out tasks, failure recovery, calibrated risk,
latency, physical resource measurements where accessible, total cost, and a
reliability guard. Passing a synthetic replay or a learned completion head is
insufficient. No external provider spending or deployment is part of this tranche.

## Operating system for the program

- Register each linked experiment's question, datasets, ten initialization seeds,
  controls, budget, tuning split, outcomes and stopping rule **before** main fits.
  Multiple lanes can progress independently under the common program; prerequisite
  failures block downstream claims rather than being overwritten by local patches.
- Keep failed/capped runs and all seeds. Report seed variance and world uncertainty
  separately. Ten seeds is a minimum design requirement, not proof of stability.
- Maintain a supervised-target inventory. Distinguish public-history-derived
  targets, simulator labels, privileged-teacher actions and self-supervised targets.
- Test exact decisions/effects and information boundaries before accepting an
  execution optimization. Reject every proposed recipe that improves cost or
  stopping while increasing physical failures under its registered guard.
- Efficiency requires measured hardware and quality/resource-matched controls.
  If DRAM counters or another measurement are unavailable, record UNKNOWN and
  narrow the claim. Never turn logical skip rates into physical savings.
- Draft PRs preserve protocols, checkpoints, curves, hashes, negative controls,
  repeatable audits and CI. Keep development claims separate from scientific
  novelty, external replication and commercial readiness. Do not merge by default.
