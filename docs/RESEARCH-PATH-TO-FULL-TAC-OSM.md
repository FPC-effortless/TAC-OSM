# Research path to a working TAC-OSM system

The target remains an agent that tracks state, retrieves relevant information, computes selectively, predicts action consequences, acts, checks outcomes and learns from verified experience. Current memory benchmarks exercise only a slice of that loop. Progress requires component changes to improve the whole agent's decisions under honest baselines, not merely produce stable activations.

The next experiments have distinct questions and completion criteria:

1. **DEV-036: make entity-local multi-timescale memory usable.** Train an unchanged local MTSK writer and a bounded-feedback writer from identical initial tensors, same data and FP64 gradient norm. Evaluate a new, larger held-out cancellation cohort and physical costs against archived local-tied MTSK, masked-local TAC and schema41. A stability fix that still guesses or services everything fails the goal. This experiment is implemented on its own draft branch.
2. **Action and simulation learning.** Add an action policy and a trusted simulator teacher that supplies discrete service/inspect/wait decisions and actual counterfactual costs. Compare ordinary future-state loss, additional teacher-action loss and verified-outcome loss with the *same* memory and compute budget. Use train scenarios generated by active disagreement queries, alongside equal-count random scenarios, then test on a sealed independent scenario namespace. Teacher agreement and actual cost must be reported separately. This uses the user's ActionOPD and active simulation ideas without assuming a language-model teacher or calling scenario generation "learning without data."
3. **Temporal event channels.** Test an order/delay-sensitive event encoder on request→cancel and cancel→request histories. Keep the memory and optimizer fixed; compare against the same-capacity ordinary encoder at H128 and H512. The retina result motivates a hypothesis about structured timing, not a performance guarantee.
4. **Identity and scale.** Replace direct entity slots with observable indirect cues and evaluate permutations, unseen identities and 16/32-entity worlds. Include the exact event table and learned schema baselines. The existing eight-way inputs and fixed query shape require a genuine interface extension.
5. **Full TAC/PLM–CDL–CASM–OSM integration.** Train the executable action loop, starting with whichever memory survived steps1–4. Compare learned CDL against simple routing, neural CASM against a plain head and the original graph executor, OSM forecasts against direct action selection, and verifier/repair against a single pass. Measure recall and total routing cost, decision accuracy, calibrated action consequences, failures, unnecessary services, inspections, repair costs and wall time. Separate component contribution from extra parameters or training compute.
6. **Confirmation.** Freeze recipes on validation, then use fresh initialization seeds and untouched test scenarios. Report distributions and paired uncertainty; register capability and economic gates before confirmation. A single 216-update pilot is an engineering result, not a working-model claim.

The next gate is practical: a candidate must both retain cancellation state and improve decisions compared with a sufficiently trained control and schema41. The broader architecture earns its place only if its connected mechanisms lower real decision cost or improve generalization in settings where explicit tables do not supply the answer.

## Current experimental checkpoint

DEV-036 and DEV-037 are now implemented and audited. A bounded local MTSK writer improved DEV-036 overall accuracy and cost over its matched unbounded writer, but reached only62.50% cancellation accuracy and lost to simpler references. With that memory frozen, DEV-037 simulator-taught action policies improved upon an untuned fixed decision threshold, yet a one-parameter threshold fitted on equal training data beat them on fresh worlds. Active case selection saved12 cost units over random within the learned-policy pair, too little to justify a broad claim. The immediate next memory test should address repeated issue/cancel ordering; the action experiment should later be repeated with gradients reaching memory after strong optimization controls.

DEV-038 changes the immediate mechanism priority: on a new reissued-cancellation split, a separately trained linear probe decoded the correct target from the existing three-value readout on96/96 holdout worlds while the original head scored48/96. Before adding a temporal channel, train and evaluate a repaired readout/head across every role and physical decision. The probe is diagnostic supervision, not a repaired agent.
