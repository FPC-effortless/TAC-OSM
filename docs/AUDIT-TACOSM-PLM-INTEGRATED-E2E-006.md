# Audit — TACOSM-PLM-INTEGRATED-E2E-006

## Purpose

E2E-006 is the follow-up functional lane required to resolve a causal
limitation found in E2E-005. E2E-005 stored multimodal observations in
entity-addressed state, but q1 and q2 targeted different entities, so q1
post-action feedback could not causally influence q2.

E2E-006 therefore keeps the multimodal input path and fixed functional
scaffolds, but makes q1 and q2 target the same entity with disjoint bit pairs.

## Causal intervention

After q1 produces an action, the environment emits an exogenous hidden binary
feedback bit. That bit is not encoded in text, image, or audio. The q1 action
therefore occurs before the feedback exists from the model's perspective.

The q2 target is:

    q2_truth = operator(payload[target_entity][i], payload[target_entity][j])
               XOR hidden_feedback

The model is never given hidden_feedback before q1. It can only receive that
feedback through the post-action update path.

Because hidden_feedback is independent of the observed payload, deleting or
flipping its state write should push q2 toward chance while leaving the
registered q2 payload/composition unchanged.

## Controls

normal receives the true feedback bit in the post-action update.

no_feedback_write replaces the feedback delivered to the update path with zero
while retaining the same true q2 target.

flip_feedback_write supplies one-minus-true feedback to the update while
retaining the same true q2 target.

no_memory clears the persistent state before q1.

All controls operate on the same evaluation episode objects and hidden
feedback values.

## Leakage requirements

The hidden feedback value must not appear in any observation tensor, query
argument, encoder input, benchmark label visible before action, or q2 query
metadata.

The q2 target is generated by the outer environment/harness after the
feedback boundary. It is used only as an action-loss target and never passed
to the model query.

The model update receives feedback only after q1 action.

Training/evaluation semantic keys must include hidden feedback because it
changes the target, and those keys must have zero overlap.

## Functional implementation constraint

The current E2E-005 update writes only successful outcomes because its update
strength is multiplied by the feedback bit. That implementation cannot encode
a binary feedback value whose zero state is also informative. E2E-006 therefore
requires a label-free signed/dual-state feedback representation capable of
storing both feedback states.

This is a functional correction, not an optimization sweep.

## Interpretation

A successful E2E-006 normal arm with a large, registered degradation in both
feedback ablations would support a narrow claim that the system can carry
post-action hidden feedback into a subsequent multimodal computation.

If normal succeeds but the feedback ablations do not degrade, the benchmark
has not identified feedback persistence.

If integrity fails, the experiment is invalid and no capability conclusion is
licensed.

No real-world multimodal, lifelong-memory, learned-addressing,
learned-operator, efficiency, scaling, or AGI claim is authorized by this lane.
