# Reviewed fixed-case local binding diagnostic

This is the fixed/default-only successor to the archived, policy-blocked source proposal. The operator approved a narrow prospective synthetic diagnostic-fit exception on 3 November 2026. The exact implementation still requires independent source review and a separately anchored one-shot resource release. Policy scope approval is not a model result, a signature of the unseen implementation, or permission for later matrices.

## Scientific question

Can each unchanged C18 GRU, phase and context model optimize eight fixed same-query cases with different four-byte values under the original focused objective? A pass is optimization evidence only. It can reflect memorization, not generalization or reliable local binding. A failure at 128 updates does not establish architectural inability. No module is assumed compulsory or useful merely because it remains in an unchanged arm.

The fixed schedule and all fixture bytes are identical to the independently reviewed v1 source proposal. One seed (18001), 128 updates per arm, 48 presentations per value and 16 per task slot. All 256 output logits remain available. State resets every batch and owners do not encode answers. Late first-answer and free-running exact-four gates are separate and both use steps 112 and 128. Final generated held-out combinations are evaluated only after all three fits are sealed; teacher-forced CE is separate from free-running decoding.

GRU has 100,323 trainable/deployed parameters; phase and context each have 99,971. The original loss is unchanged: natural CE + .25 task CE + answer CE + 3 first CE + .01 balance. Native balance is active and GRU balance is its original zero. AdamW lr .003, betas (.9,.95), weight decay .1, epsilon 1e-8, clip norm 1, foreach=False. No tuning, rescue updates, checkpoint selection, early-success stopping or automatic retry. No architecture-ranking/selection, superiority, real-world capability or deployment-readiness claim is admitted.

The paired epsilon and varying-input designs are retained only in the archived v1 proposal/history. They are not selectable by this protocol or this release. No new architecture/module, real corpus, pretrained checkpoint, GPU or paid service is introduced. Historical 15 FP32 failures and the separate 20 diagnostic failures remain unchanged.

## Exact proposed work

One three-arm matrix: 384 attempted/completed optimizer updates, 795 candidate forwards, six reference forwards, 402 candidate backwards, 18 reference backwards, six model constructors and six optimizer constructors. Three optimizers exist solely to verify restoration and never step. Three future-tail poison calls are included in the 795 forwards. Per arm: 65,536 input tokens, 512 total training rows, 384 task examples/first targets. Ordered exposure hashes are registered and tracked from actual batches.

Aggregate limits remain 360 CPU seconds / 600 wall seconds, including implementation audits, evaluation, checkpoint replay and process supervision. The numeric child has 345 CPU seconds with an early stop at 340, one CPU thread and 8 GiB address-space cap. Caps are ceilings, not evidence the experiment will complete. Interrupted or unequal-budget matrices are incomplete and cannot produce a winner.
