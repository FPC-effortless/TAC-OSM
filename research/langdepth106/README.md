# LANGDEPTH106 — four versus eight layers at approximately one million weights

The user requested both LANGCACHE104 depths on Tiny Shakespeare. This frozen,
owner-authorized exploratory study trains actual learned models and reports
held-out next-byte prediction, generated text and measured CPU resource use.
It does not claim general architecture superiority or independent scientific
qualification. The separate signed research gate is preserved unchanged.

## Fixed models and training

| Allocation | Residual width | FFN width | Layers | Trainable/deployed weights |
| --- | ---: | ---: | ---: | ---: |
| Four wider layers | 120 | 224 | 4 | 998,024 |
| Eight narrower layers | 72 | 120 | 8 | 999,784 |

The parameter gap is approximately 0.176%. Both have four heads, key/value
dimensions 16/16, write rank two, local KV window 128 and chunk length 32;
positive fast/slow banks, the separate signed field, RoPE local attention and
tied 256-byte embedding/readout are active. The explicit-key byte-record API is
disabled. Neural source bytes remain pinned to LANGCACHE104 implementation
`b567f4c68a73106781555496c44145939efd1d92` and PNDS companion PR #104.

Each allocation receives seeds 10601, 10602 and 10603. Every fit has exactly
4,096 AdamW updates, batch eight, sequence 128: 4,194,304 predicted training byte
presentations. Paired seeds receive identical sampled source offsets, from a
dedicated RNG independent of model initialization. Carried state resets between
independently sampled training windows; there is no artificial carry across
unrelated offsets. No DEV/TEST data are supplied to the training process.

The schedule warms to 0.0003 over 128 updates and cosine-decays to 0.00003.
AdamW uses betas (0.9,0.95), epsilon 1e-8, weight decay 0.1 and gradient norm
clipping at one. Both use FP32 and two CPU threads. No per-arm tuning, adaptive
stopping, extra data or best-validation checkpoint selection is allowed.

This is a depth/width allocation comparison. The eight-layer allocation also
holds twice as many per-layer cache states (591,872 versus 295,936 FP32 tensor
bytes after the recent window fills). Parameter parity does not imply equal
state capacity, training FLOPs or runtime. Actual costs accompany quality.

No preprocessing vocabulary is fitted; all 256 byte IDs remain available.
Every input and target stays inside its source partition. Fit staging contains
only `train.bin` and metadata. Held-out files are a separate artifact. Source
receipts are provenance records, not independent external attestations.

Only the fixed final step-4,096 checkpoint from every registered arm/seed is
evaluated, after all six pass checkpoint/configuration/source/exposure audits.
Primary scores reset state every 128 inputs. Secondary scores carry state
continuously within each held-out partition. Both count every legal next-byte
target exactly once, including the final partial window, with summed losses
divided by actual target count. State resets between partitions.

Metrics: NLL in nats, bits per byte, perplexity and next-byte accuracy. Three
paired run differences are reported individually and aggregated without treating
correlated byte predictions as independent experimental replications. The final
TEST comparison is declared before fitting and has no tuning or selection role;
its once-only journal is a local execution guard, not an externally sealed ACL.

Generation uses `ROMEO:\n`, 512 generated bytes, temperature 0.8 and sampling
seed 10699. It uses the full 256-symbol distribution, with no hand-coded alphabet
filter or sample selection. Raw bytes and display text are preserved. Generation
prefills once and consumes each sampled byte once through recurrent state.

## Execution and evidence

The reviewed workflow prepares source, runs optimizer/resume/evaluation fixtures,
then tests both allocations with eight standalone optimizer updates. Only if both
smokes pass does it launch six independent full fits. Every fit preserves loss
curves, sampled offsets and atomic initial/intermediate/final checkpoints with
model, optimizer, scheduler metadata, global Torch/Python RNG and dedicated
sampler RNG. CPU checkpoint readback reloads original tensors and optimizer and
requires exact next-byte logits on a TRAIN-only probe. Interrupted-resume fixtures
must reproduce uninterrupted weights, optimizer state, data order and RNG.

Every full fit is bounded by 2,700 seconds; GitHub jobs have 50-minute timeouts.
No GPU quota is consumed. Full FLOPs and energy are unmeasured. Inference timing
uses the same fixed CPU workload and reports prefill, recurrent decode and owned
cache storage separately from quality. Failed/partial attempts remain evidence.

The ordinary qualified-training planner correctly retains its independent-source
and signed-attestation blockers. The current user request and persisting explicit
owner authorization instead permit this separately labeled exploratory CPU run,
as in LANGCAP105. No signature is manufactured, no qualified gate is marked PASS,
and no old protocol or trained result is rewritten. The original frozen protocol,
source receipt and count/planning record are available under this study and
`research/langdepth106_results/`.

Tiny Shakespeare can show learning and compare these two allocations under this
recipe. It cannot establish broad language intelligence, long-memory exact recall,
reasoning, commercial usefulness or superiority over Transformer/Mamba/BDH.
