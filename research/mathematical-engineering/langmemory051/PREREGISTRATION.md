# LANGMEMORY051 — prospectively frozen key residency versus continuation entropy

Registered 2026-10-29 **before any original publisher FIT numerical measurement**. This is a no-fit source-only decomposition following the original negative 050 study ([PR #581](https://github.com/FPC-effortless/TAC-OSM/pull/581)); new work in issue #582 and PNDS Issue #67. Preserve every old original-source failure and trained checkpoint.

**Hypotheses:** (1) finite hash-table key loss dominates poor next-byte source continuation retrieval more than the K2/K3 Misra–Gries continuation representation, (2) prior-source exact context frequency entropy is highly heterogeneous. These are testable mechanism claims, not proven ahead of source measurement.

**Actual publisher cohort:** original legally licensed 14 CPython 3.13.0 FIT owner documents, source checksum and partition frozen from 050; previously explored by many 045–050 trials, therefore not independently confirming architecture. Three original source prefixes and event positions fixed: <=1536 stride4, 4,928 positions; <=4096 stride4, 13,245 positions; <=8192 stride8, 11,784 positions. Every score uses only previous observations; original x[t] is introduced into all indices after scoring at t. Each owner resets independent state. Exclude protected TEST and new neural model training.

**Primary decomposition:** For exact key k of last3 source bytes at position t, a strictly prior-only evaluator maintains a per-owner exact continuation histogram c_t(k,v), occurrence count n_t(k)=sum_v c_t(k,v), distinct prior continuation number d_t(k), conditional entropy H_t(k)= -sum_v (c_t(k,v)/n_t(k))*log2(c_t(k,v)/n_t(k)), first historical occurrence and last historical continuation. Never use future frequency for a candidate's actual eviction/update. Evaluate context seen vs new, single vs multiple observed continuation bytes, d>=3, unique vs repeated and genuine prior source delays >64/1024/1344/4096/8192. The last/source-majority comparison is purely evaluative.

**Bounded arms:** reuse exact actual previous source implementation classes for K2/K3 two-way hashed 1344B and4096B, old K1 8-byte source table at same bytearray budget, recent64 ring fallback, plus exact full history counts as explicitly unmatched storage reference. Crucial: count whether a genuine previous context key is physically resident in the bounded hashed table at query, separately from the returned continuation value and correct original label.

**No-key-eviction ablation:** an owner-local Python dict keyed by exact 3-byte context holds K=2 or3 independent Misra–Gries value counters. This model uses **UNBOUNDED memory** and must never be used as a deployed or equal-budget baseline. Update it with the same original continuation at every observed time and same decrement rule as fixed table. At queries it uses same recent64 fallback, but no hash key collisions/evictions; compare it to fixed K2/K3, full original source majority and original K1. It isolates the value-representation failure only as an upper-bound engineering control; MG may still fail to predict majority because the counters are approximate.

**Comparison and uncertainty:** report correct / *all eligible original source positions*, answered/coverage, exact historical key recoverability, key resident vs missing with an earlier observed instance, resident but zero-count candidate, relative source majority/last outcome, owner-level counts, empirical entropy on prior-only prefixes and actual read/write CPU. Record all source hash receipts. Equal stored byte counts are NOT equal time/computation and Python objects/backing diagnostic dicts are excluded from fixed candidate buffer. The no-eviction oracle has no matched storage, cannot be called a winner at fixed budget.

**Failure rule:** Original 050 anchor 4,928 source targets, original K1 1344 correct=781 and full exact reference correct=1465 must match; extended targets 13,245 and long 11,784 must match. Any changed causal source owner or stale original baseline means FAIL. No changing evaluation procedure after actual result to claim a win. Full source-independent heldout, PNDS Lean proof and neural architecture/GRAPH011 recomputation are separate future tasks. This study does not report neural TAC next-byte NLL or peak activation VRAM.

**PNDS obligation:** Ideal MG heavy hitter theorem for a *permanently resident key*, K counters and no uint16 overflow is conditional and does not transfer to finite hashed memory after eviction. Formal math in PNDS Issue #67 is not implemented/proved by this diagnostic. Avoid inference of neural whole-graph proof or new model performance from source-lookup counts.
