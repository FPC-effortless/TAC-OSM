## Important methodological and resource limits

1. This is **a new real physical source task not used for original ME097 training** with a chronological first-half experience/second-half one-shot holdout; however, nonparametric memory *may adapt online* from previous holdout outcomes by a preregistered prequential protocol, so this is not a static no-adaptation test. No same-frame unknown candidate action was evaluated; recorded commands are lagged genuine observations only, not do(a) identification or verified safe policy.
2. Both memory systems use at least **256×(8 learned query coordinates+14 stored source residual values+1 utility)×4=23,552 additional FP32 bytes** of external cache payload per memory instance, PLUS hash map, source identity/provenance, any controller caches, model weights and Python/runtime allocations. Original **608B primary neural recurrent FP32 state remains intact** and cannot be called total solution memory.
3. The hash/utility stage is state-dependent and **sequential online AFTER the parallel neural scan**. It does not preserve exact original end-to-end scan for utility writes; no extra full-network mathematical Lean proof and no learned parameter-budget-head-to-head. All comparator arms use the same original pretrained network, actual source and events and no new neural optimizer updates. CPU read/write measured and recorded as outcomes in artifact, not artificially matched.
4. Per-event squared-loss frames in 25 episodes are temporally dependent; five original checkpoints do NOT provide 125 independent episodes; no p-value or headroom inference from repeated frame counts. Source sibling metadata showed consolidated v3 file although the old publisher README describes v2 episode files. Strict early pre-score errors [#40210947148](https://github.com/FPC-effortless/TAC-OSM/actions/runs/40210947148) (Python record closure / missing first episode condition) and [#40211081570](https://github.com/FPC-effortless/TAC-OSM/actions/runs/40211081570) (dataset path mismatch) are preserved in CI. Only reader and progress code changed pre-first-scoring; no metric threshold, neural model, original registered memory utility equation, LSH hyperplanes or retention schedule was tuned after seeing results.
5. A model that slightly reduces an already tiny velocity residual while introducing extra CPU/RAM must demonstrate **cost-adjusted physical value** beyond matched simpler baselines. The current <1% improvements do not meet preregistered competence thresholds and should not be called meaningful physical forecasting breakthroughs.

## Research implication and next experiment (no posthoc EWA002 tuning)

Evidence across *two actual real data experiments* now indicates: similar historical observations sometimes help a predictor, but the evaluated per-item utility feedback rule **does not reliably improve ranking**, even with the utility-vs-FIFO eviction confound isolated. This does not prove all possible usefulness-aware memories fail; it defeats **this specific** design at the registered datasets and budgets.

Potential next registered experiment on a FRESH source: condition an **event novelty/retention criterion on a physically derived kinematic residual and source-verified regime**, first test *forecast harm under memory lesion* at the whole ensemble level with properly logged future observed outcomes, and compare against a small physically informed Kalman/servo residual prior and matched vector-store alternative. Investigate **cheap multi-stage hashing** independent of score reranking, memory compression/recency and provenance. Preregister source, budget, training resources and calibration gates BEFORE any test; keep six active TAC families and original ME097 source/weights intact. Do not run unregistered hyperparameter search on candy exposed episodes to optimize EWA002.
