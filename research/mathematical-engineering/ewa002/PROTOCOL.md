## Why the next experiment
EWA001 showed neutral 256-slot 8D-key/14D-residual cache helped frozen ME097 on *previously exposed* cabinet DEV, but utility feedback made it worse in all 5 seeds. Both memories lost badly to an elementary constant-velocity extrapolation and the original LSH collision scoring exceeded its 32-per-query budget. EWA002 must (a) build on velocity, (b) isolate hash candidate retrieval vs memory utility, (c) evaluate on an authentic source task not previously used by ME097 and never score original protected ALOHA TEST.

## Frozen original shared model; fair arms
All original ME097 seeds 97001..97005, 95,874 real-fitted weights each, SHA-checked vs immutable original FIT_INDEX, original cabinet FIT normalization and learned 8D query. Original model only supplies a SOURCE-CAUSAL matching key, not the predictive base. Original key generated from x[t], action[t-1] and legitimate recurrent source history only; no same-frame action or future observation. No neural fit or parameter change. All arms use the EXACT same real observations, cache key vectors and earlier genuine outcomes, memory size, top-K, correction cap and held-out episodes. The base is genuine velocity extrapolation (2 x[t] - x[t-1]), not persistence or frozen model output; frozen original predictions are separately reported for calibration reference, with no hidden mixing.

Shared cache 256 entries × (8D source key, 14D standardized source-derived velocity residual, utility float) in FP32 = **23,552 extra float bytes** per arm instance, plus source/timestamp, hash bucket map, runtime, model parameters etc. This is NOT inside native 608-byte FP32 recurrent scan state. FIT-only previous event residual = clip(x[t+1]-velocity[t],-.08,+.08); normalization uses original ME097 FIT-pinned cabinet scalers. Correction is .25×weighted 14D clipped residual with topK=8 and softmax temperature=.25. No changed/rescored hyperparameters after new-task outcomes. Utility and neutral use same FIFO insertion+eviction, so utility **cannot** alter which records exist, isolating retrieval weighting.

Four prediction arms per original checkpoint on same cuts:
- velocity (no memory).
- velocity+exhaustive_cosine (256-slot bounded full scan, exact top8 keys, controls hash approximation).
- velocity+hashed_cosine (11 seeded Gaussian hyperplanes seed20261025; query bucket plus radius1 Hamming neighbors; exact cosine top8 within hash candidates only, return zero correction if empty).
- velocity+hashed_utility (identical hash candidates and same shared FIFO/cache values, rerank selected candidates by cosine + .20× past utility; no utility-based eviction). Actual utility values are maintained separately and updated after outcome only.

**Per-memory measured realized marginal utility, after x[t+1] ONLY**: for selected candidate i, compute current full-ensemble output yhat and a counterfactual model-output *leave-one-out ensemble* yhat_minus_i, renormalizing other TOPK weights; use delta_i=(L(yhat_minus_i, actual)−L(yhat, actual))/scale; norm uses fixed squared standardized real velocity residual quantile from ONLY first25 cache warmup outcomes (90th percentile, clamped min 1e-6), clip[-1,1], EMA=.05. This tests **model-internal memory benefit**, NOT causal contribution to the physical world or counterfactual real action outcomes. When only 1 candidate, leave-one-out is zero correction. No future observed label used to select/weight a memory at that same step. Utility credit only to actually selected historical memory entries. All memory bank writes happen AFTER predictions/outcome verification and are sequential, not part of the original exactly affine parallel state scan.

## Hash-only diagnostics (separately from ranking)
At EACH evaluation event, measure hash candidate *set* size and hit; compute full cosine top8 over the current FIFO bank in an AUDIT ONLY path; report fraction of exact cosine top8 candidates PRESENT in the raw hash shortlist (index recall), and the final hashed_cosine top8 overlap separately. Utility final top8 overlap is a DIFFERENT metric and never called hash miss rate. This audit never supplies missing candidates to the hashed predictor.

## Success/disqualification, fixed before scoring
1. H1: similarity-exhaustive memory improves heldout episode-weighted standardized MSE over constant velocity by >=1%, in all five checkpoint seeds; no moving-motion regime >5% harm relative to velocity.
2. H2: utility indexed memory improves heldout episode-weighted MSE by >=1% against same indexed cosine cache in all 5 seeds (retrieval gain), no moving-motion regime >5% harm compared with hashed_cosine.
3. H3: hashed cosine vs exhaustive cosine has <32 scored candidates per query on average, >=70% of full cosine exact top8 available in raw hashed candidate set and >=90% nonempty-hit on heldout queries.
4. Overall SUCCESS only if H1, H2 and H3 ALL pass; otherwise original negative result must be published exactly. The original measured velocity and persistence are mandatory baselines; a model that cannot beat velocity may not be called a qualified physical world model.
5. No new trained model, no broader robotics/vehicle authority, no 608-byte total-memory claim, no empirical p-value treating overlapping frames or multiple seeds as independent. Present per-episode counts, domain transfer and original-data provenance. CPU walltime an outcome only.
