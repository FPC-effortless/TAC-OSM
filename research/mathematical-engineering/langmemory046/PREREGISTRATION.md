# LANGMEMORY046 — prospective original-source matched-verifier controls

Registered 29 October 2026 before the first actual original-source CI measurement. This is an internal no-fit follow-up to LANGMEMORY045A draft #575 and issue #574. Preserve all original source/negative evidence.

**Questions:** Is selective expensive history verification a better use of exactly K historical verification calls per owner than random calls from all positions, or random calls only from positions where cheap A/B is absent/disagreeing? Can a per-owner incrementally updated exact-context count index return identical answers while lowering the scan cost, and what actual growing memory does it require?

**Cohort and time boundaries:** All fourteen original PSF CPython 3.13.0 FIT owners, first at most 1536 bytes per owner. Predict only original position t>=128 with t divisible by four. Inputs are raw x[0:t] only; 3-byte key x[t-3:t] observed before target, never future. A: last64 exact 3-byte-key continuation majority. B: frozen 256-bucket FNV Boyer-Moore sketch. Cheap fusion: A if available else B. Costly V: exact earlier same-owner context continuation majority; ties choose lowest byte. Update state and exact index with original x[t] only AFTER scoring that position.

**Primary masks:** select = t divisible by 5 and (A missing or B missing or disagreement). For each owner, random_all = K SHA256-ranked positions, random_uncertain = K SHA256-ranked uncertain positions, where K equals number of select calls for that owner. Precommitted random seeds 11,29,47,83,131. No rank or K depends on outcome correctness. K is retrospectively determined from the prefix-only gate cohort, so the call-matched random control is a diagnostic, not a deployable online random policy. Periodic every-fifth and full-index are additional descriptive references.

**Metrics:** Number verified; naive linear scan positions for each mask (equal call count does not imply equal scan work); correct predictions and coverage over ALL original target positions, conditional correctness and distant-match coverage; repairs/regressions relative to cheap; per-owner and by-random-seed uncertainty. Exact full-history index must produce identical answers to independently recomputed naive source scan for every original query, before comparing its speed. Report per-owner full index key counts, compact lower-bound bytes, actual recursive Python heap estimate, per-observed-byte index updates, index read vs naive scan CPU observations (no mobile/energy claim). Full index grows with source, unlike bounded TAC neural state. Budget parity is call count only, not learned parameter/training budget or whole-model compute.

**No-fit scientific conditions:** Source original FIT-only, no new neural model/training, no original or new checkpoints touched, no protected TEST, no GPU, no model promotion or architecture winner. The same source owners were already used in 045A, hence no fresh independent generalization; original matched-compute neural study and PNDS Lean+Python actual graph remain OPEN. Source audit and phone CPU planner before results, deterministic constructed future-poison tests, full original results and negative/error attempts retained. Fail on source, parity, time-boundary or index disagreement. If index wins merely by storing full growing history, this is an engineering storage-versus-retrieval result and does not establish better TAC memory.
