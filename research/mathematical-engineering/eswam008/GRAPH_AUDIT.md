# ESWAM008 — actual input-to-output mathematical graph audit

Source audited: src/tac_osm/variants/exchange_world_action.py, selective_exchange_world.py, kinetic_exchange_world.py at original ESWAM004 branch. This is source analysis, NOT a trained improvement or passed scientific gate.

## Tensor shapes and graph
B=batch, D=14 state dimensions, A=14 logged action dimensions, W=90 fast/slow width, M=16 memory width, S=8 identity slots, R=3 evidence roles.

Input observed state x[B,D], observed mask[B,D], logged action[B,A], elapsed time[B], source entity ID[B]. Input features[B,2D+A+1] -> encoder Linear(43,W), SiLU, Linear(W,W), tanh -> z[B,W].
Key/query/value each z[B,W] -> Linear(W,M). Retrieve old prediction memory state.ids[B,S], keys[B,S,M], values[B,S,R,M], occupied[B,S,R] for same source entity ID and unverified role. Correct prior fast via observed-versus-predicted innovation projected M->W. Fast gated update from concatenated z and corrected fast -> [B,2W]; slow gated update from concatenated *new* fast and prior slow -> [B,2W]. Write source observed role; retrieve factual memory; readout concatenated fast/slow/memory [B,2W+M] ->64; next-head ->2D (mean residual, positive scale); logged action imitation head ->A; prediction code ->M and write to separate unverified role.

ESWAM003 additionally computes observed previous-step normalized velocity and a movement logit from [fast,slow,velocity,command error] then rational adaptive shrinkage of physical residual. ESWAM004 adds an EMA kinetic trace and source-logged command-change trace, uses noisy-OR movement gating and a learned measured velocity continuation. Its original five-seed real-robot results show movement point-estimate improvement but robust stationary and calibration regressions; this graph audit cannot erase that failed gate.

## Mathematical bottlenecks
1. ExchangeMemory.write iterates each batch item in Python and uses data-dependent nonzero/slot selection, repeated tensor cloning and in-place indexed writes. This creates graph breaks and poor parallelism, and makes large B or many actors costly.
2. ExchangeMemory.retrieve also iterates each batch item, uses variable-length boolean advanced indexing and Python bool conversion, then softmax and stack. Vectorized masked batched dot products would remove Python dependence for fixed S.
3. The symmetric/antisymmetric exchange computes two learned maps of swapped ordered pairs, but the final updated memory is only torch.lerp(old,incoming,scalar_gate). The exchange features only parameterize the merge rate. There is no separate persistent antisymmetric state and no demonstrated causal contribution to real accuracy.
4. Source IDs are supplied; the model does not infer identity. The eight fixed slots are per B item, NOT eight independently jointly processed traffic actors. A model that processes each actor in its own B element cannot learn cross-actor interactions merely by increasing S.
5. Slow update requires newly computed fast. A proposed parallel proposal would derive candidate_fast and candidate_slow from the same previous state, then exchange information in a second phase; it changes the mathematics and MUST be trained/tested, not called an equivalent speed optimization.
6. One-step recurrent updates depend on preceding time states, so arbitrary time parallelism is NOT automatic. Within-time batch, actor and slot processing can be parallelized; parallel prefix/associative scans need an actually associative transition family, not the existing nonlinear gated recurrence.
7. The existing 14D robot physical head is not automatically suitable for 2D traffic actors; source field units, time gaps, physical residual and actor interaction must be adapted and guarded.

## Candidate computational graph, not yet implemented
At each real observed t, independently encode all actually visible actors in a padded/masked [B,N,F] batch, with no invented observations. Form source-ID exact-match [B,N,S] and role occupancy masks; batched matmul similarity and masked softmax; retrieve factual, predicted and verified roles independently. Parallelize per-actor candidate fast and slow maps on prior state and observed input, then fuse with gated cross-level residual. Compute next-actor prediction as measured velocity physical prior plus bounded evidence-gated learned correction. Write new observed values using masked scatter with deterministic collision refusal and explicit overflow, never silent eviction. Do not convert unverified prediction into factual observation. Candidate graph must be audited for all-missing inputs, gradient flow through value updates, no cross-entity memory aliasing, finite confidence, role isolation and batch/actor permutation consistency.

## Qualification and nonnegotiable gates
A vectorized rewrite must first reproduce original old-memory retrieval, collision refusal, merge and write results (including gradients) on adversarial identities/roles and varied batch sizes; exact semantic preservation is a software gate, NOT real-world capability. Any new joint actor computation or parallel fast/slow redesign is a NEW model requiring matched authentic training against GRU and causal attention on frozen ESWAM007 source splits and identical measured-velocity reference. Predeclare actual memory slot capacity, source co-visibility, parameter count, optimizer/data/update budgets, measured training FLOPs, source actor-cluster uncertainty, physical +10/+30 errors, stationary error and calibration. A positive real-world claim requires a held-out source result and independent replay, not passing unit tests. Equal CPU inference time is not compulsory.
