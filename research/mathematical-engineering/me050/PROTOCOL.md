# ME050 — genuine per-user chronological memory, not feature-coordinate recurrence

Registered 2026-10-21 before any new ME050 training/heldout evaluation. Follows the completed failed ME049 paired Criteo study (PR315) and the separate Hillstrom RCT study (PR314). Does not retune exposed ME049 targets or replace their negative records.

## Actual capability under test
On true identified (anonymized/reindexed) individual user histories, predict a *new observed real click* for the currently displayed video given its logged action identity and up to 12 strictly earlier recommendations and observed clicks. Unlike ME048/49, the 12 history tokens here are **actual past interactions sorted by timestamps**, not synthetic tasks or reinterpreted feature coordinates. Target is immediate observed click, not next latent physical state, causally identified intervention improvement, future trajectory simulation, autonomous System 2 reasoning, or deployed recommendations. The native system resets state for each 12-event window and is **not** a continuously persisted 1000-step memory. This is an honest limited temporal-memory prerequisite.

Full source published by Chongming Gao et al., *KuaiRand: An Unbiased Sequential Recommendation Dataset with Randomly Exposed Videos*. The mirror has a CC BY-SA 4.0 LICENSE; verify origin and license constraints independently before any production use. At execution: download exact immutable revision, hash entire original CSV, check required real `user_id,video_id,time_ms,date,is_click,is_rand` fields, non-null integer values and no corrupt outcomes. Publish exact downloaded bytes+SHA+record counts in results, **not raw users' source rows or per-user predictions**. No artificial click labels.

Only FIT rows with calendar date strictly BEFORE 2022-05-02 are parsed before training; skip later rows without parsing action IDs, timestamps or rewards. Stage 1 derives chronological FIT histories only. After all eight model/optimizer/RNG checkpoints are SHA-frozen, parse full source including DEV dates 2022-05-02 to 2022-05-04 and sealed TEST dates >=2022-05-05 and <=2022-05-08. Freeze one source SHA at first fetch, reject any change. The final heldout is genuinely future calendar time on original source. Development and TEST labels cannot tune a candidate or a model threshold. Histories for later events may incorporate *strictly earlier observed outcomes*, including already-occurring earlier test events: this is an explicitly declared **prequential, teacher-forced** evaluation and not a closed-loop policy deployment.

For each user, sort `(time_ms, CSV-row-index)`, then each eligible target must have **at least 12 previously observed events from the same user whose timestamp is strictly earlier**. Use exactly the most recent 12 such events and preserve order. Each token: hashed observed video ID (bounded 4096 buckets), prior actual click (0/1), log1p elapsed real hours to current event, prior hour of day. Candidate action features: current hashed observed video ID and current time-of-day only (before click). No future user labels/other users' outcomes, causal propensity estimates, or per-user embedding fitted from future outcomes. Predeclare failures for insufficient temporal overlap or absent positive/negative click outcomes in each calendar split.

## Controlled experiments
Models: (A) TAC fast32/slow32 + genuine 8x8 associative innovation memory on chronological 12-event windows, (B) **the exact same TAC architecture, same active parameter count and training indices** but history event order deterministically reversed without changing the 12 observed events, (C) GRU64 chronology, (D) context pooling of the same 12 history events. Two seeds 50001/50002; identical sampled actual FIT training example indices, batch64, 500 AdamW updates, fixed optimizer settings. All four share identical candidate embedding/token encoder/head; expose true parameter counts, optimizer CPU seconds, total training examples and FLOP differences. TAC A vs TAC B has identical learned parameter count and number of recurrence operations and observed-data multiset; machine CPU difference is measured and must be reported. GRU/context have potentially different parameter/CPU counts and are **NOT claimed fair architecture-level winners** unless all parameter/data/compute controls align. Under equal steps+samples, actual CPU may be unequal; don't claim global full-resource fairness from equal optimizer updates.

## Preset scientific gates
Primary pooled future TEST observed-click Brier (smaller better), secondary log loss, plus FIT/DEV rates, test click base rate and each model's scores per seed. Zero-parameter real FIT click-rate predictor; current-video frequency smoother may be added with strictly FIT-only counts, never tuned on TEST. Require chronological native to beat **same-native reversed history** and pooled-context/GRU Brier *for both seeds* to claim evidence for a competitive TAC capability on this source. Only chronology-vs-reversal within TAC is a near-compute-matched controlled test. Cluster bootstrap over **heldout users** (200 draws; user IDs never in published artifacts) for TAC-vs-reversed and TAC-vs-GRU paired loss differences; positive improvement needs both lower pooled error and 95% cluster interval excluding no gain. If any gate fails, preserve negative findings; do not alter protocol or test cohorts.

Original real weights/optimizer RNG and exact original test probabilities replayed on pinned AVX2. Numerical fixture tests may use generated events for correctness checks only, never performance evidence. No model merge, promotion or claim of market/state-of-art, real causal action-selection, long-horizon 512-event retention, multimodal/language understanding or commercial autonomy. Follow-up should scale to the complete 1K standard+random histories and later to real rewards and linked actions using rigorous doubly robust or prospective evaluation.
