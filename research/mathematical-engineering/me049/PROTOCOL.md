# ME049: Genuine supported treatment actions and action-dependent TAC memory
Registered **2026-10-21, before training or opening new ME049 outcomes**. Independent research question after ME048's failed positivity/support audit; stacked on PR313 without altering original weights or negative result.

## Purpose and hypotheses
Test whether adding a *real logged action to the native recurrent state transition*, rather than conditioning only the readout, improves held-out **observed-action** visit/conversion prediction and the stability of learned action choices. Do not label this multi-step world-state learning. Criteo users have no persistent IDs, visit histories or chronological sequences. The existing 12 covariates are feature coordinates, not past time steps. No factual outcome for the unassigned treatment is ever used as a supervised label.

## Architecture comparisons and targets
Four genuine-data-trained models: ME048 native action-head TAC, ME048 GRU, ME048 context MLP, and **new action-state TAC**, which adds a learned 2x16 treatment embedding into each of the original 12 covariate tokens *before* the established fast32/slow32+8x8 associative transition, separately for the proposed action. All use same typed visit/conversion goal and logged-action-only BCE losses. New native state model learns `Q(x,a,goal)`; action may alter recurrent transition instead of only a final index. This is **not** action-conditioned physical state evolution through time.

Two seeds 49001/49002; 800 AdamW updates (batch256, LR 0.001, weight decay 0.0001, clip1); same 160000 FIT rows and exactly same sampled row indices across all architectures for each seed. Log active parameter counts, exact update/sample parity, actual optimizer CPU and inference-time cost. Architectures are eligible for head-to-head **equal-update matched-data** comparisons; if trainables differ or optimizer CPU/FLOPs are unequal, no fair *whole-resource* superiority claim. Explicitly record numeric parameter difference and CPU mismatch; do not call it compute-matched.

## Measures and prespecified decision gates
Primary heldout TEST: observed-action visit Brier; secondary visit logloss, conversion Brier/logloss, both per arm and pooled, with exact logged treatment. Require both treatment groups in FIT/DEV/TEST and report each group's factual predictive errors and base rates to avoid pooled-only false improvements. Each architecture independently learns a policy `1[Q(x,1,visit)>Q(x,0,visit)]`, no after-TEST calibration or threshold changes. Exploratory policy scoring against both fixed actions may use `p_sample=.5`, inverse-weighting and doubly robust prediction, with 200 paired bootstrap replicates and effective sample size; assumptions and limitations must be explicit. No policy gain, causal identification, or independent general intelligence unless externally validated assignment propensities and fresh policy trial exist.

Predeclared research test: new action-state TAC **must beat original TAC on pooled and both treatment-specific TEST visit Brier in both seeds**, and **must beat both GRU and context pooled visit Brier in both seeds**, to qualify *accuracy evidence for this sampled task*. This does not establish general architectural superiority because compute differs. If any gate fails, retain all negative outcomes and do not promote. All models must replay their saved logits exactly on the pinned AVX2 reference, with original weights and optimizer states; software-only generated tensor tests never count as intelligence evidence.
