# LANGSCALE071 — exact same-label original context-length scaling of frozen 250K/500K/1M models

## Frozen before any new context score
[LANGSCALE070 original run #40871491842](https://github.com/FPC-effortless/TAC-OSM/actions/runs/40871491842) trained 9 original publisher-source, exact checkpoint+optimizer+RNG models. Same-source 3-seed FFN capacity mean exposed DEV NLL improved at every tier and seed. We do not retrain, tune, reselect seeds or access protected TEST in this study.

Hypothesis: **does additional source context** improve original next-byte prediction at an otherwise fixed real source target position in each scaled TAC model? A recurrent model trained with 128 source context bytes might improve out to128 and might **degrade** at 256 because that is beyond its training horizon. Record actual nonmonotonic outcomes, not posthoc selection.

## Source-locked target and input protocol
- Re-read and hash-verify original PSF CPython3.13 original publisher FIT and four previously exposed DEV documents and source membership, no cross-doc concatenation.
- Each DEV owner contributes **exactly 64 deterministic target positions**, chosen by `numpy.linspace(256,len(owner)-1,64,dtype=int64)`. Frozen SHA over the resulting **256 identical observed original next-byte target positions** with owner/time identity and value. 64 distinct positions/doc, all t>=256.
- At each target position `t`, input at length `L` is ONLY the authentic *same owner* byte slice `[t-L:t]`, output is original label `raw[t]`; 256 labels identically scored for all contexts and checkpoints, no future input. Input context lengths **16,32,64,128,256**; each model resets state at each context and predicts last logit `logits[:,-1]`. This is **not streaming carried state** and L256 extrapolates outside trained L128, not a long-memory claim.
- Reuse **all nine original checkpoint arms** (p250k 250133 /p500k499623 /p1000k1000239 x seeds1701,1702,1703) from exactly [#40871491842](https://github.com/FPC-effortless/TAC-OSM/actions/runs/40871491842); restore one original checkpoint per job with source/optimizer/RNG receipts, validate each SHA using the original source-verified aggregate and strict model `state_dict`. First replay original exposed 4096 DEV NLL within 1e-6 of its exact reported 070 score. Then evaluate new 256 source target coordinates once per context.
- CPU GitHub ubuntu-24.04, PyTorch2.10.0+cpu, 2 intraop/1 interop, no optimizer/no GPU/Kaggle or protected TEST. Compute raw NLL/top1/Brier, per-document NLL, original input/target SHA, CPU process seconds for same 256 observed labels, artifact for every arm. Aggregate refuses missing/duplicate models, changed parameters/source labels or context input hash mismatches.

## Interpretation gates
No neural retraining; no model/architecture superiority over SSM/Transformer/GRU; no model quality certification. The ability to read 256 reset bytes is not verified 256-stream persistence, and may fail on actual mobile hardware. The single 256-position cohort is within **previously exposed DEV**; targeted evaluation on previously exposed source cannot establish unseen generalization. The bigger FFN tiers have different trained parameter and FLOP budgets. Stronger context NLL means source reset-window sensitivity only, not a universal scaling exponent or information surviving long persistent state. Compare actual results at each L with **same exact 256 targets** before describing a monotonic trend; record all failures.
