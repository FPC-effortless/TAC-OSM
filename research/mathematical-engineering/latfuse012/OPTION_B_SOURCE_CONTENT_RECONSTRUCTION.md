# Option B after LATFUSE012 — falsifiable authentic-source reconstruction-first protocol (NOT YET FIT)

**Status:** research design only. No new model trained or promoted. LATFUSE012 result established the limitations: privileged original WRITE-key read aligns cos~0.92 with its writer value at H64, yet wrong keys align~0.76 and trained original value vectors for matched high/ordinary observations already align~0.62; the actual historic read aligns only~0.28. Event write residual~1.3× later ordinary source-write medians. Actual/event source 24-pair rankings can be inverse EVEN BEFORE TRAINING, making content/label/episode confounding an independent issue. Frozen-source all results [LATFUSE012 PR #470](https://github.com/FPC-effortless/TAC-OSM/pull/470). A source-free fixed512 delay count sweep [PR #471](https://github.com/FPC-effortless/TAC-OSM/pull/471) found probability degradation with more intervening memory writes, but skipped writes also skip alpha decay, so capacity and forgetting are not isolated. Neither result qualifies native factual recall.

## Primary test — genuine historical CONTENT reconstruction (B0)

Train **one clean source-registered fixed-horizon H64 historical retrieval objective** first, using original 2014 or prospectively acquired lawful genuine longitudinal station records with verified independent ground-truth past targets. Keep writer, two heads×8D keys×16D values, entire original 256 cells, alpha/beta routing, fast80/slow80+16 source slots and original time-only historic-clock query architecture *identical* to original LATFUSE008. Do NOT add time-addressing A or novel admission/erase yet. Target actual observed original source PM2.5 numeric magnitude after past normalized transformation, optionally source-recorded high/ordinary under explicitly frozen threshold, fed to supervised LOSS only, never fed to future historical query. Study target should include ordinary middle values, not just easy extreme +150 vs <=35 selection, to prevent labels trivially encoding episode/regime. Training case feature consumes only observations until true query time t, owner/source, missingness, last legal values and requested past-time clock; strict authorization and no future sensor values/labels in question.

Why reconstruction before contrastive: making learned q and key cos large can become a geometric shortcut while the value16 content fails to encode the actual physical quantity. The real-source oracle high cos and wrong-key high cos directly motivate *content specificity*, not another overlap metric.

Protocol: freeze minimum updates/data before results (prior32 updates insufficient), two+ fixed original seeds and exact 2013/2014 or newly acquired source-owner chronology with preserved authentic missingness, source-before-training normalization. Fit exactly same actual event/source records, station/day cases, lag64 and source forecast objective to two native heads:
- **B0**: historical query/memory gets actual past source-content reconstruction target; keep existing source encoder/writer unchanged.
- **Control**: same params, compute, observations, seed/train schedule and source-content reconstruction objective but historic event decoder relies on fast/slow/entity current state *without associative memory*, still retaining original matrix for same +6h forecast. This tests incremental native memory usefulness.
- **Optional B1** *only separately after B0 baseline is independently evaluated*: same B0 plus source-written key/query alignment with **hard negatives** from other actual recorded writes within SAME monitoring station history window; no artificial source future targets, no oracle anchor key in deployed model input. Retain current 8D key matrix shape and 6800byte state; count auxiliary negative-indexed training evaluation instrumentation separately.
- **A** distinct later factorial: time-aware write AND read source metadata, when and only when known legally at inference, with same full compute/resource budgets and B0/B1 isolated. Random Fourier clocks/elapsed metadata should not be presumed useful merely for representational novelty.

Training criterion: use actual source-value proper errors (masked magnitude MAE/MSE or predeclared distributional likelihood) and optionally physical high-event Brier, never just key cosine. Query negative source-written keys must be captured at training time from real source as **offline auxiliary supervision**, not stored at streaming inference. Any cached historical keys or 64-token candidates in deployment would violate original fixed recurrent-state contract; training temporary activations permitted if bounded and accounted in training memory budget.

## Preregistered event retrieval success and controls

- At 64 real source hours, require previously unseen original-source owner/time heldout **continuous physical value reconstruction** improve over **both source current/clock nuisance and equally trained fast/slow/entity nonassoc**; the win must be recorded by every declared seed or reported mixed honestly.
- At H16/H128/H512 zero-shot after fixed H64 training, report source-real observed absolute physical MAE, normalized MAE, event balanced accuracy, Brier, registered source-matched event paired rank, and proper calibration under missingness, with no claim of superiority from internal FIT data.
- **Top-1 within-source-window recall metric**: at each genuine query, compare the model's native real-value forecast against an 8-way fixed candidate set of authentic past values of the SAME monitoring station in a registered temporal window; include the true recorded timestamp/value and seven other genuinely observed nearby candidate timestamps (not future, no evaluation target used as query input). Use source candidate labels ONLY after native prediction to score correct matching. Freeze tie-breaking, candidate ordering, success >chance=12.5% threshold before optimizer, source-exclusive episode bootstrap and station-heldout split. A score test requiring offline enumeration is an *evaluation probe* and not a claim of constant-memory exact token address retrieval.
- Compare actual whole read zeroed, specific true-source event-step write bypass, and original write-key privileged oracle as READONLY diagnostics to show native path, not source-oracle query benchmark masquerading as capability.
- Add current PM2.5, last valid PM2.5, source site+calendar, 24h pre-event level, source temporal episode/date/time matching and initial untrained scores; avoid mistaking systematic score polarity for memory fidelity.
- +6h original physical multi-channel MAE vs last-observation persistence and masked Gaussian NLL/empirical channelwise coverage; reconstruction success must not silently degrade all-channel forecasting or claim calibrated decision intelligence.

## Full integrity gates before any new training

1. Source authorization, original provenance SHA, raw physical masks/age/last, source-owned station clocks and all source outcome truth, and independent unexposed real-world evaluation held sealed. Earlier May–June/July2014 data have been exposed and cannot be used to promote the next variant. No original protected 2016–17 numerical source without separate permission.
2. Parameters inside original95k–105k and live/deployed exactly matched <=1%, original FP32 recurrent state1696+16flags=6800B unchanged. No dead dummy weights. Query/read architecture is native, source-only targets are used in loss but not query.
3. Independently measure actual **COMPLETE** forward+autograd+optimizer training FLOPs <=1% between matched B0 and control and later B1, same train updates, source input/target/sample-order/optimizer LR/weight decay/seeds. Original LATFUSE008 supported-op parity alone was not a qualified full-operator FLOP count; document any mismatch rather than hiding it.
4. Preserve trained weights, AdamW optimizer, RNG, original source normalizer and station/time eligibility/sample hashes, all checkpoints Git-replayable via clean checkout CI; anti-cheat/ref-source owner leak and accidental future-target query audits.
5. PNDS source refinement: exact-recurrent-gated-affine operator and clock/query source contract including state count, finite precision/AD and probabilistic laws. Existing small Lean count proofs do NOT establish native factual recall or correct Tensor computation.
6. A model improving only training source labels or privileged oracle cos is NOT a validated capability. Need independent real source +6 forecasts and true historic reconstruction against matched controls.

**Decision:** Explicit **source-recorded historical CONTENT reconstruction** is the first Option B objective. Contrastive (InfoNCE or pairwise within-window hard negatives) is a distinct later source-registered auxiliary arm, not bundled into B0 or declared sufficient on geometry alone. Time-aware A is third. Avoid making a new architecture from exposed diagnostic results until full fair-budget and source integrity gates pass.
