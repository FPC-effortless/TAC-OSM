# LANGMATH095: source mathematics and causal persistence diagnostics

This implements the October 30 mathematical review as an isolated, **no-fit**
research package. Historical model implementations, checkpoints and negative
results remain unchanged. Passing software fixtures does not validate the
structure-centric intelligence hypothesis or establish predictive usefulness.

## Run and inspect

NumPy is the only dependency of the mathematical and persistence diagnostics.
PyTorch enables actual-source forward/backward and candidate checks. The public
`tac_osm` runtime dependency contract is unchanged.

```sh
python scripts/phone_lab.py plan research/phone_queue/langmath095-no-fit.json
python -m unittest discover -s tests -p 'test_langmath095_*.py' -v
python research/mathematical-engineering/langmath095/audit.py --output /tmp/langmath095.json
```

Output files are exclusive-create, preserving earlier evidence. Missing
PyTorch, source, checkpoint or outcome evidence stays INCONCLUSIVE. The CPU
workflow installs PyTorch and checks the existing architecture-independent
probe contract; it performs no optimizer steps or GPU allocation.

`scans.py` implements sequential, balanced work-efficient and chunked matrix
and diagonal scans, with initial states, masks and numerical/gradient tests.
The original source scan remains the default. Timing these fixtures is not a
decode speedup or deployment measurement.

`candidate.py` wraps a deep copy of an eligible baseline. Default behavior
delegates to the original forward. Optional policies change one mechanism:
bounded aligned writes, bounded positional features, or removal of the base
concept graph. The graph lesion retains stored weights but reports its 512
inactive parameters; it is not a matched active-parameter training arm.
Multiscale retention requires an explicit factory that reinitializes the copied
upper forget projections. It is not a fixed-checkpoint lesion. No policy is
selected or promoted on fixture scores.

  --checkpoint /authorized/model.pt --inputs /authorized/observed-windows.npy \

Only registered 500K and 10M factories are accepted. The receipt binds exact
checkpoint, input and reviewed source hashes and must declare a FIT/DEV

a publisher. No network fetch, arbitrary adapter import or protected TEST

CODEVALUE003 seed1701 checkpoint at step10240. Its byte input is constructed:
this diagnoses trained weights and source numerical parity, **not** real-data
prediction quality, learned structures or useful persistence. The original
checkpoint is read-only and its internal qualification is unchanged.

Named gradients include zero, missing and nonfinite tensors. Real CPU source
parity is separate from still-open CUDA FP16/loss-scaling obligations. The
10M model remains window-reset only; the registered window probe does not
claim full-model carried-state semantics.

## Structure, persistence and scarcity

`persistence.py` exposes a trusted callback adapter that separates acquisition
from a **query-only** prediction. Controls reset all components, zero individual
components, exchange matched donor contents, and mutate the acquisition payload
after state creation to detect replay/alias dependence. Every cache and state
metadata field must be declared. Python callbacks/closures remain a trust
boundary; these tests cannot prove arbitrary-code noninterference.

Feedback arrives after a committed forecast. Missing feedback must leave state
unchanged. Availability is not truth verification; a model-specific verifier
and authentic outcomes are needed to qualify a verified write. Output changes
demonstrate dependence only. External truth metrics remain separate from
learned-structure and causal-utility claims.

The full resource ledger includes acquisition, retrieval, verification,
computation and retained storage. Missing costs are unknown, not zero.
Acquisition must not disappear from claims about relevant-history scaling.
