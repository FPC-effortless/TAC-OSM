## P1 — Edge-Lite mobile artifact: measured deployment, no implied qualification

First engineering milestone: one originally trained, hash-verified model checkpoint -> explicit state-in/state-out export -> offline mobile runner -> independent numerical comparison with the same source-authorized chronological inputs -> physical-device latency/memory/energy report. Do not claim a mobile product from a 100k parameter count or an ONNX/Core ML/ExecuTorch file alone.

1. Select an *existing original checkpoint* and model-specific exporter. Audit supported causal/scan operators and specify input, action, state, reset and output tensor contracts. Keep full parameter count, learned state, external caches, normalizers and runtime overhead visible. No new training or replacement of scientific gate.
2. Package model and exact SHA256, pre-export checkpoint SHA256, export version, input/output dimensions, numerical reference policy and raw artifact size. The portable offline verifier in scripts/validate_mobile_edge_package.py checks identity and manifest structure; it **does not** verify functional parity or run a phone.
3. On a real entry-level Android reference device, record software/OS/CPU, actual execution backend and fallback, p50/p95 latency, 30+ measured steps, peak RAM, artifact and runtime size, battery/energy methodology and offline operation. Capture exact per-step inputs/outputs when legally shareable, verify against Python per dtype/tolerance and test state reset and true streaming versus batch. A desktop/CI timing does not qualify hardware.
4. Expose Android/iOS SDK only after hardware and identity evidence gates pass. Core ML and ExecuTorch are potential formats, **not yet exported or verified** in this work. A runtime cannot authorize actions; Woyengi/app-owned state remains authoritative.
5. Distinguish PACKAGE_INTEGRITY from PARITY, REAL_DEVICE_EVIDENCE and MODEL_CAPABILITY gates. Every missing gate is UNKNOWN/BLOCKED rather than PASS.
