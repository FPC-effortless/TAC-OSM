Original publisher API metadata must be fetched and SHA/MD5 and original size recorded before parsing. No unverified third-party derivative CSV allowed. Offline data cannot be treated as observations acquired prospectively in real time unless each prefix's recorded timestamp and source entity identity allow it.

**Critical difference from robot episode file embargo:** The entire BPI source is packaged in a **single archive** that contains FIT, DEV, and TEST cases. A trusted partitioning stage will necessarily download/parse that whole archive, even before model training. Thus, DO NOT claim protected DEV/TEST raw source bytes were physically never downloaded. Instead run an explicit **trusted source-partitioning** process that writes separate hash-pinned case-level FIT/DEV/TEST artifacts, encrypt/quarantine or prevent the model/trainer from reading held-out partitions before the original nine checkpoints are frozen. The source preprocessor may inspect all raw records for partitioning but is barred from computing heldout label frequencies, choosing model features based on heldout outcomes or exposing target-derived case attributes to training. If such separation cannot be enforced, empirical anti-cheat gate = BLOCKED. The trainable model must never see future outcomes of an ongoing source case. Original data has timestamp ties, source ordering and censored incomplete cases; ambiguous within-time ordering and incompletes remain INCONCLUSIVE or excluded with audited counts.

Source input vectors, [B,T,14] observed and 14D logged observed event action: any learned vocabulary/normalizer/transform derived FIT **only**, prefix sees source-visible activity, amount if known at application opening, event timestamp, prior offer status, resource when logged and prior executed action. Label `application eventually accepted/rejected/cancelled` or next recorded offer event must be defined from source ontology; case final status is a FUTURE LABEL and CANNOT enter source input. Clarify right-censoring and time-shared leakage. NO causal do(a), applicant approval recommendation, credit underwriting, discrimination/risk or actual individual lending decision authority. ## Mathematical engineered paired controls
Causal source-indexed learned admission inside **existing 8×8 = 64 FP32 floats**:
`M_{t+1} = M_t + γ_t (v_t - M_t k_t)k_tᵀ`,
`k_t = one_hot(offer_slot_t)`, `γ_t=β_t(1-α_t)` with strictly bounded learned gates from original shared world encoder. Exactly one source-authorized memory column receives the update; every OTHER entity's old column is unchanged in exact arithmetic. This composes right-affine transforms for bounded-depth parallel temporal scan, and supports O(1) streaming step updates. Unlike source-uninformed learned address, this controls cross-offer interference; BUT this alone is not an extra-world-model architecture, and whether it learns useful outcomes is unproven.

**Comparators**: source-aware selective slot, native content-addressed TAC model with the same original FIT features, and *false source-slot randomized at FIT source* as identity-negative control (same weights/compute/state). Parameter and state budgets must match (95,907 weights and nominal 664 bytes if wrapper is exactly 14D state/14D action and original 16D slow /64 associative). If entity-indexed wrapper has a different input/head, verify and report any mismatch, no false 95,907 claim. Match 3 registered seeds (39001,39002,39003), model initial tensors, fit cases/time prefixes, optimizer and updates, batch/window sampling, ACTUAL full forward+backward FLOPs (not just parameters), episode/case clustered uncertainty, and physical runtime. Add GRU and matched SSM, context-free/read-off baselines with carefully matched source features and real compute.

**PRIMARY task** eventually source-confirmed terminal case outcome measured from a decision-time prefix, and offer outcome with source offer ID (if reliable): macro-F1, AUPRC where binary and outcome prevalence, Brier/calibration, expected decision cost with explicitly preregistered false-positive/false-negative costs on retrospective events. Need natural long-history dependence, not trivial next-activity guessing. No action recommendation/safety status.

**Strong prereg threshold to be finalized BEFORE opening a single heldout outcome:** across 3 seeds, after full compute-matched training, source-addressed > common fast/learned memory, identity-corrupted control, and GRU/SSM by at least 2% relative retrospective delayed-outcome loss with case-clustered uncertainty, no worse Brier or rare-event AUPRC, no future source feature, real long histories evidenced. These are not results and this protocol does not precommit to a numeric threshold without known FIT prevalence/cost; register final experiment-specific pass/fail gates prior to any DEV file opening.
