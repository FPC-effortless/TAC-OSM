## Why PAR-MEM-008 replicated a previously recognized problem

PAR-TIME-001/005 rebuilt a narrower `TimeAwareParallelResidualWorld`: **96,639 weights**, streaming **88-value running prefix + 64-cell matrix + two clock scalars = 154 FP32 scalars** (616 bytes plus Boolean and count). It carries no typed/source-authorized `owner` and `last_hour` in its stream state like ME100. It does not have LATFUSE004's two separate 80D fast/slow persistence states, 16 owner slots, 256 memory cells, per-head source-aware soft write router, historical query head, or content-reconstruction loss. Each original key is `normalize(address(embedding(observation, availability, time)))` rather than DIAGKEY004's shared known-ID addressing.

Thus **PAR-MEM-008's real trained key effective rank 2.67/8 over 256 observations is not an unresolved problem that all TAC versions had failed to address.** It is a diagnosis of the *particular simpler new branch*, and earlier remedies may have been dropped from its state/learning objective. Nor is a high-rank Fourier key by itself a proven neural memory remedy. Source-state figures are NOT comparable without disclosing the different task, external entity metadata and deployed memory cost (154 floats versus ME100's 152 plus identity/age versus LATFUSE004's 1,696 floats+16 occupancy flags).

## Historical engineering decision — reuse rather than invent

**Priority A: carry forward source-owner and source-observed admission** from ME100 before any new trained long-history claims. Timestamp/ordinal and source identity must be available BOTH at write and query; model time may not guess arbitrary entity keys or leak historical target values. Preserve causally correct missingness and scan-only input-conditioned gates.

**Priority B: preserve DIAGKEY004's successful software memory interface and its negative evidence.** Share known-key addressing, protect read-only query operations, tie value codes and disentangle retention from write strength. The synthetic result is proof of trainability at immediate delay under its own task, NOT evidence of H128 real ability. Source versions have different mathematical update orientation and retention bounds: explicitly prove operator correspondence before porting.

**Priority C: reuse LATFUSE004 2H soft/8D routing and source slots as the existing candidate** rather than silently rebuilding a competing "new head" with fewer features. The 2014/2015 aggregate real forecast failures and >1% supported-FLOP factorial comparison stand. The key diversity hinge and route-balance need source/target-dependent information pressure, not only uniformity. Equal erase law and actual source-content read must be tested.

**Priority D: reuse LATFUSE018 trained content reconstruction and LATFUSE008 meaningful fast/slow head control** to test real old-fact information, not only cosine. Demanding a concrete time-specific original reading be recovered is stricter than measuring key cosine/rank. Keep the already registered negative time-specificity gate from [frozen study #495](https://github.com/FPC-effortless/TAC-OSM/pull/495); do not retune the repeatedly exposed 2014 period into a "new" held-out pass.

**Priority E: no automatic experimental promotion.** The next work should be one optional integrated historical-source-informed candidate within the same SIX families (not a seventh): original parallelizable input-only scan where mathematically valid, source-authorized owner and selective writes, shared lawful event identity address, independent retained content, protected query, direct query-conditioned source-content read, original temporal forecasting and calibrated uncertainty outputs. Retain CED as an optional postscan bounded concept program, not force it into a nonlinear same-scan recurrence. Verify real advantage above mean/last value plus re-trained genuine source/no-memory/GRU/SSM controls with 95k–105k active weights, <=1% parameter and complete training FLOP differences, matched source/data/optimizer, 5 seeds, authentic truly independent legal event/cohort, original checkpoint replay and complete PNDS Lean/Python input-output contracts.
