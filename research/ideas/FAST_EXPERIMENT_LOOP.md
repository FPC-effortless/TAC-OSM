# Fast capability experiment loop

This workflow shortens time to a useful capability finding while preserving the research gates. The queue is advisory: independently registered studies may proceed in parallel when their own gates pass. Treat two concurrent fits as a resource-planning recommendation, not a scientific barrier or fit authorization. Keep exactly six active model families on the shared core.

1. **Parallelize low-cost review.** While one owner defines the capability and source, run independent implementation, mathematical, and data/provenance reviews in parallel. Reconcile disagreements before the registration is frozen. Do not duplicate model families or create fits as a form of review.
2. **Qualify the evidence before training.** Audit the original source, license, timestamps, entities, missingness, authentic outcomes, exposed DEV lineage, and truly untouched evaluation cohort. Use only bounded FIT-only screening when it is separately registered, strictly source-guarded, and its decision role is explicit. Screening does not open protected TEST or replace final evaluation. Existing 2015 exposed UCI501 DEV is not untouched; UCI501 TEST 2016-2017 remains closed.
3. **Freeze a complete registration.** Specify the falsifiable capability objective, prior-art gap, complete source-to-output graph, splits, baselines, thresholds, all planned arms and seeds, actual model parameter receipts, data exposure, training and tuning compute ceilings, evaluation conditions, failure handling, and every attempt. Validate `FAIR_COMPARISON.json` with `scripts/validate_research_parity.py --phase preflight` before any optimizer step. All prospective trained models, including single-model studies, must have 95,000–105,000 trainable and deployed learned parameters. Matched trained architecture comparisons also require no more than 1% parameter gap and matched real data, training/tuning budgets, and evaluation conditions.
4. **Run one frozen five-seed complete-model study.** Train the full registered model recipe with no hidden retries, posthoc threshold changes, favorable-seed selection, or extra tuning. Record every original attempt, interruption, failed gate, negative result, and source/checkpoint hash. For architecture claims, rank only arms that actually trained and satisfy the registered matching gates; a plan or untrained baseline is not a competing result.
5. **Freeze bytes before scoring.** Commit or otherwise immutably freeze all original model, optimizer, RNG, and required replay artifacts before opening any registered scoring cohort. Keep protected TEST closed unless the independent registration explicitly authorizes its use and every access gate is satisfied. Run the final parity/resource receipt on actual training evidence before interpreting held-out architecture comparisons.
6. **Require independent replay and report all findings.** Have a clean independent replay verify original checkpoints, source, forecasts, and summaries. Report positive, mixed, failed, interrupted, and null findings together with uncertainty and cohort limits. A failed full gate stays failed; do not relabel it using a subgroup or rounded metric.

The shortest valid loop is the one that resolves a capability uncertainty with the least authorized compute. It does not require four-way attribution ablations before establishing whether a complete capability works. Attribution can follow only when the primary evidence makes it useful. A preflight-valid queue entry is only a registration candidate: source qualification, mathematical engineering, actual implementation/resource checks, and data-access controls remain independent live gates. No queue declaration authorizes a fit. A registration validator, literature review, code proof, or passing software test is not intelligence evidence by itself.
