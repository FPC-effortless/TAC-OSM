# TAC-OSM — Compulsory Capability Progress and Intelligence Evidence Standard

**Effective: 2026-10-23, prospective.** This is the binding **claim and promotion standard** for all new TAC-OSM ME/DEV results, model-development summaries, cross-domain claims and investor material. It supplements, never weakens, the authentic-data rules in `REAL-WORLD-EVIDENCE-RULES.md`, checkpoint/replay policy, prospective **95,000–105,000 real trainable AND deployed learned parameter** requirement, and **≤1% trainable/deployed parameter difference plus identical real-data, exposure, training/tuning-compute and evaluation** rule **when making architecture-superiority comparisons**. CPU runtime is recorded, not forced equal. All past results remain unchanged, including negative results and old model sizes.

## What “getting smarter” must mean

**Operational definition:** A model acquires a *demonstrated capability* when it performs a well-defined task on authentic observations with measurable predictive skill beyond a nontrivial appropriate reference. It *improves that capability* when the new frozen model produces a **material, reliable and repeatable improvement** on exactly the same real prediction problem and eligible cases, without disqualifying regressions. A claim of **broader intelligence or generalizable world modeling** additionally requires independently unseen conditions, transferable knowledge/state or new decision-relevant skills; it cannot be inferred from raw parameter count, more training targets, new architecture modules or passing software tests.

Intelligence is **not** a single scientifically established scalar. Never manufacture an “IQ score”, percentage completed, guaranteed generality or an assertion that a model is closer to AGI. Report a **multidimensional measured capability portfolio** with failures as visible as wins.

**Priority:** Train the **integrated model** to improve useful skills; do not require an ablation campaign, novelty proof or fresh GRU fit for every development cycle. **Comparative architectural superiority is a distinct scientific claim** and still requires fully matched-control research. A practical comparison of two deployed systems may show improvement despite unequal resource inputs if disclosed; it cannot establish a superior architecture or data efficiency.

## Mandatory prospective rules (FAIL CLOSED)

1. **One explicit claim, defined before testing.** Before fitting or accessing a new sealed cohort, record the exact old frozen model, new candidate, training sources, observed-at input contract, prediction time, task, horizon(s), all eligible cases, prediction target, scoring code, original source/split hashes, seeds, primary metric, minimum material change, guardrail metrics, uncertainty method and final decision rule. For a newly added skill without a prior model output, register an informative available reference and minimum utility threshold rather than declaring a win by construction. Do not retrofit the claim after reading results.
2. **Authentic data and real temporal causality.** Primary success evidence must use original externally collected real histories and independently observed future records/outcomes. Prediction uses only fields actually known at the forecast time. No source-ending-as-verified-business-completion, future-derived features, hidden ground truth, synthetic outcomes, artificially selected retrospectively known midpoints, or censored examples silently counted as correct/incorrect. State exact source rights and label-availability times.
3. **A sealed evaluation stays sealed.** Development and previously exposed TEST may guide improvements but are forever **DEVELOPMENT evidence** for any future study on them. For confirmation, register and freeze a genuinely untouched chronological/site/entity cohort or independent real source; its metrics, predictions, labels and tuning information must not have influenced model design, parameters, selection, thresholds or stopping. If the holdout has been reused, mark it **EXPOSED** and replace it for independent confirmation. One registered final opening, then seal a newer cohort for future changes.
4. **Identical question for before/after.** An improvement claim requires the **same** real cohort IDs, eligibility, prediction age/decision time, labels, event vs EOR treatment, horizon, metric implementation, class mapping, scoring aggregation and censoring convention. Different horizon, longer survivor traces, task, context, supervision or population = **different capability task**, not numeric progress. Re-run the previously frozen version on the newly defined task when legally and technically feasible; otherwise mark **not directly comparable**. Do not compare ME069 hindsight-midpoint accuracy to ME071 fixed-six accuracy.
5. **Hard, useful reference before promotion.** Evaluate the best appropriate simple/practical method with the same permitted decision-time information: persistence, empirical state/count/Markov model, hazard/survival method, rule-based operations reference, servo dynamics or other established domain reference. Report the prior complete TAC-OSM model as well when a same-task prior exists. A new architecture need not beat every method to show a new skill, but failing the strongest practical method forbids “better prediction for customers” or “SOTA” claims. A matched GRU/other neural arm is mandatory **only to claim architecture superiority**, with strict resource parity.
6. **Actual learned capability, not just mechanics.** Successful normalization, causal masking, memory routing, finite gradients, stable rollout code and 1,000+ passing tests are **ENGINEERING_VERIFIED**, not learned predictive ability. Genuine real-data-trained checkpoint, original complete source/model/optimizer/sampler/RNG/score material and **independent clean-checkout original-score replay** are required before `TRAINED_REPLAY_VERIFIED`; replay confirms reproducibility, **not** correctness/generalization or an improvement.
7. **Report all relevant outcomes, not the best-looking number.** For event classification report proper negative log likelihood, Brier, accuracy, error by difficult/rare branch and all eligible counts. For multi-step forecasts report **each pre-registered horizon**, unconditional event-plus-source-boundary and conditional event scores separately, plus target survival, missingness and valid future counts. For time output proper time likelihood, pinball/interval scores, empirical coverage vs nominal, median/p90/p99 width and tail/failure extremes. For alert use event precision/recall, missed opportunities, false alarms, lead time, selective coverage and credible real costs when available. Never swap the primary metric for one that improved.
8. **Pre-register a meaningful effect, uncertainty and reliability.** Choose a **nonzero, domain-justified minimum practical improvement** in the primary metric and limits on critical regression metrics **before** seeing outcome data. Use the original independent entity/case as the uncertainty unit (cluster paired bootstrap or prespecified suitable equivalent); 95% two-sided confidence interval and point estimate must support the **positive, pre-registered minimum** for `INDEPENDENT_GAIN`. A bootstrap CI from repeated horizons, paths, five model seeds or multiple reports over the **same case** is not independent sample size. Report all per-seed results, uncertainty from model fitting, and a fixed multi-metric/horizon selection rule; 4/5 seed-direction agreement is the default for five paired seeds unless alternative preregistered justification exists. Explain multiple-testing selection and confidence-interval assumptions.
9. **A gain can be vetoed by a meaningful regression.** Material undercoverage, severe overconfident/wide timing tails, higher missed-risk or false-alert burden, outcome-specific failures, increased leakage, unsafe action or unacceptable deployment cost must be reported and can veto an **overall improvement** even where the primary NLL wins. Mark `MIXED_TRADEOFF` for NLL better but calibration/time/critical cohorts worse. Do not hide worse horizons behind an average. A new skill may be **ADDED_BUT_UNRELIABLE**, not “smarter overall.”
10. **Free-running trajectory claims need joint tests.** Direct 1/2/4/8 horizon heads prove **multi-horizon marginal forecasting**, not physically or process-consistent full future sequences. Simulating or rolling out eight steps demonstrates **trajectory generation software**; learned trajectory intelligence requires actual scored event order/path validity, accumulated event/time proper scores, survival/censoring correctness, failure compounding, and authentic outcome prediction **without teacher-forced future observations**. Use truthful autoregressive vs direct-head labels.
11. **Persistent-state, adaptation, planning and counterfactuals are separate.** Carried recurrence ≠ useful learned long-history retention; entity routing ≠ learned identity discovery; masked input ≠ missing-event reconstruction; changing activation/state ≠ changing trained weights; retrospective action association ≠ causal `do(action)`; ranking recommendations ≠ realized policy utility. Claim each only when a preregistered factual real-world evaluation tests the specific skill, with real length/exposure and independently observed actions/feedback if relevant.
12. **Independent confirmation and transfer require genuinely new people/equipment/cases/sites.** `INDEPENDENT_GAIN` needs an untouched real cohort and authenticated source/score ledger. `TRANSFER_REPLICATED` requires additional independently collected real distribution(s), pre-registered transfer procedure, independent effect and relevant failure reporting; same BPI2012 institution/history split cannot demonstrate cross-domain intelligence. Report all sites; never promote a positive selection from several datasets without adjusting selection uncertainty.
13. **Selection and parameter budgets must be honest.** Record **all** training fits, tuning trials, seed outcomes, actual effective trainable and deployed learned parameter counts and prior/lookup model bytes; for future fitting maintain the repository's 95k–105k live model gate and all original checkpoint integrity controls. If previous and new models used different data, epochs, exposed labels, tuning budgets or deployment lookup tables, classify a gain as a **whole-system/development comparison**, not evidence of architectural learning efficiency. For a claim that TAC's architecture beats another neural architecture, enforce ≤1% parameter discrepancy, identical data order/exposure, FLOPs/update *and* total compute/tuning privileges, exact evaluation. Wall/CPU time is NOT a parity requirement.
14. **Pre-registered independent corroboration is not replaced by enthusiasm.** The owner, researcher or assistant cannot declare a stage `PASS` from a narrative, README, diff, CI badge or assistant opinion. Confirm Git original model bytes, exact dataset/source hashes, raw paired per-case predictions, independent score regeneration and the locked decision rule. Preserve both successes and failures in Git; no editing original labels or relaxed thresholds after results. If data/receipts are missing, report `BLOCKED/UNKNOWN`, not a positive result.
15. **Product and investor usefulness are an entirely different gate.** Forecast skill does not prove workflow value, actual SLA improvement, commercial savings, an accepted customer pilot, regulatory approval, safe authorized automation or investors' willingness to fund. Those require independently collected, legally authorized *prospective* customer evidence and actual time/cost/action receipts; publish distinct capability and value claims.

## Fixed promotion vocabulary — every study has an explicit tier

| Tier / exact label | What it says | What it does **not** say |
| --- | --- | --- |
| `DESIGN_ONLY` | Proposal, math or code has not produced a verified original fitted real-source model | No trained intelligence |
| `ENGINEERING_VERIFIED` | Software/unit or simulated diagnostic passes | No learned predictive capability |
| `TRAINED_REPLAY_VERIFIED` | Real model fit, original tracked checkpoints and independent real-score replay verified | No improvement or generalization guaranteed |
| `DEV_CAPABILITY_OBSERVED` | An actual skill scored on honest authentic DEV or exposed old TEST, with denominators and appropriate reference | Not independent confirmation; cannot claim new scientific superiority |
| `DEV_GAIN` | Same-task, same-cohort **frozen prior-vs-new** directional improvement, predefined primary metric; disclose regressions and differences in training/data | Provisional, not independent generalization or better architecture |
| `MIXED_TRADEOFF` | Material advance in at least one defined skill but guardrail or other primary skill regresses | Not “overall smarter” |
| `INDEPENDENT_GAIN` | Same-task rigor, sealed untouched real cohort, practical reference, meaningful preregistered primary improvement with appropriate CI/seed evidence, all critical guardrails pass | Not universal general intelligence or customer ROI |
| `TRANSFER_REPLICATED` | Independent gain reproduced across distinctly sourced real conditions with all source/safety limits stated | Not generalization beyond tested domains |
| `OPERATIONAL_VALUE_VERIFIED` | Authenticated prospective pilot with pre-agreed outcomes/costs, measured net utility and permissions | Not autonomous or causal intervention success absent independent evidence |
| `REGRESSION`, `INCONCLUSIVE`, `BLOCKED` | Material negative results, insufficient evidence or irreproducible source/score | Must never be silently converted into success |

These are **evidence classifications**, not automatic linear levels or an arbitrary model intelligence score. A specific new skill can be `DEV_CAPABILITY_OBSERVED` while an old one remains `REGRESSION`.

## Default scientific success conditions for an independent improvement claim

All apply; if any is unknown or fails, do not issue `INDEPENDENT_GAIN`:
- Hypothesis, frozen models, exact ID split, cohort, primary and safety metrics, **nonzero** practical threshold and seed/CI procedure preregistered before outcome access.
- Independent real entity/case units sufficient for the preregistered power/precision target. **Recommended minimum 100 independent cases**, not a universal guarantee of power; below 100 requires explicitly preregistered statistical justification and cannot rely on repeated seed/horizon counts. Report exact denominator and absent-target eligibility.
- Same-case **paired** primary result with all case-level raw score records; point benefit positive and 95% confidence lower bound **strictly greater than the prespecified practical threshold**, plus default ≥4/5 seeds in the beneficial direction.
- Appropriate practical reference assessed on the same allowed inputs. Guardrail behavior within preregistered limits across critical subgroups and all planned horizons; no material hidden regression.
- All fit/tuning/checkpoint/replay/source identities confirmed by independent audit; cross-domain/decision claims satisfy their additional separate factual requirements.

**Secondary evidence:** A meaningful relative change on development data can be encouraging (e.g. 4% lower NLL), but **do not substitute an arbitrary universal 1%, 5% or 10% metric delta** for domain economics, uncertainty or preregistration. If the exact previous model cannot execute the new skill, report an authentic strong reference and **new skill validated on DEV**; independent confirmation still required for robust generalization.

## Required scorecard for every future ME/DEV report

Publish a compact **same-model, same-task, same-cohort comparison** wherever the skill already existed, plus separate new-skill readouts. The human-readable report and original machine-readable prediction/score bundle must include:
- Study and fixed Git/PR refs; `old_full_model` and `candidate_full_model` **checkpoint hashes**, trainable/deployed parameters, exact training budget, prior state bytes and training data identity.
- `claim_type`: **new trained skill / same-task capability improvement / architectural superiority / transfer / prospective operator value**. `tier` from the fixed vocabulary above.
- `observability`: original legal real-data source+hash, registered FIT/DEV/untouched/EXPOSED split, time/entity/site boundaries, online-available features and label availability, censoring, missingness, original independent case IDs and query age/horizon.
- `planned_primary`, `minimum_useful_gain`, `measured_primary` (case-level point/CI/seed distribution), eligibility denominator and all predefined guardrails/secondary metrics (including worst credible slice/long tail), selection/search attempts and any changed budgets.
- `integrity`: Git original model+optimizer+RNG bytes for each fitted seed, original prediction and score files, runner environment and independent clean-checkout audit; leaked/previously exposed test status.
- `decision`: **PASS / FAIL / INCONCLUSIVE / BLOCKED**, exact failed conditions, **what actually improved**, **what worsened**, **what remains unverified**, next integrated capability target and operator-value hypothesis (customer evidence separately verified or `UNKNOWN`).

**Never report only a favorable summary average.** Include seed spread and context/age/horizon strata; 95% interval width without coverage is misleading, and record-ending prediction must be labeled a source-boundary proxy. Publish the full result even if the answer is that the model **did not get better**.

## Enforcement and audit rule

Every future research PR must link this standard from its preflight/registration and include the human-readable capability scorecard. A prospective automated checker may reject **missing declarations, wrong tiers, absent hashes, inconsistent counts or unsupported claim-promotion metadata**, but **cannot independently prove label availability, actual real-world utility, source ownership, statistical validity or customer value from self-declared JSON**. Independent audit of original model outputs and observed records is always required. No change to this standard may retroactively alter historical claim thresholds; amendments require a new dated version and prospective activation.
