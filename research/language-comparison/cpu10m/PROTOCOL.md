# Ten-million-parameter CPU inference screen

Freeze before forward passes or timed requests. This engineering screen measures the CPU cost of larger native CSL byte-language configurations as an input to training decisions. It has no language-quality endpoint.

* Source CSL125R2, precise memory and the byte-only head pattern from TAC-OSM a7ec101ee67fce09aaf42b5c8e880586f77be0e9. Scale the geometry only. Both configurations have 4 roles, 3-tap convolution, chunk size 32, local attention every second layer, 8 query heads and 4 KV heads, attention window 128, one final tied 256-byte readout and FP64 carried memory. Four layers use width 448, state width 64, feed-forward width 1392. Two layers use width 640, state width 96, feed-forward width 1920.
* Use upstream nanochat GPT and its KVCache at a825e63f81e62e2e9fd38655e9b2e39417620545, 4 layers, width 448, 8 query and KV heads, default SSSL, context 512, 256 byte vocabulary. Use torch.nn.GRU with 2 layers, embedding and hidden width 896, untied 256-byte output with bias. All arms must have 9.5M–10.5M trainable and deployed parameters and fit within 1% of each other. Mamba-3 remains a separate GPU obligation.
* CPU, 1 PyTorch thread, batch 1, FP32 projections, native memory precision, greedy argmax. Use the first 32 or 256 UTF-8 bytes of this protocol, already converted to IDs before timing. Generate 16 bytes including the first from prefill. Time per request includes cache initialization, prefill, 15 cached steps and every argmax. Exclude model loading and text tokenization. Reset all state each request. Use seed 1901 per arm. Check cached logits at the first generated position against full-context recomputation (rtol/atol 0.0001). A failed check invalidates timings for its arm.
* Warm twice per arm/profile. Time 24 complete requests per arm/profile in seeded shuffled blocks with all arms present once per block. Save raw timings, median whole request and first-token times, p95 decode-step time, live parameter counts, library/hardware details and cache parity errors. Inspect the two depths separately. Report the 20% cost screen against each baseline at each length. No optimizer, corpus labels, protected splits, weight publishing or GPU allocation in this diagnostic.
