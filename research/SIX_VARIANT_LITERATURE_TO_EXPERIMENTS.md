# TAC-OSM six-lane external literature-to-real-experiment map

**Research audit 2026-10-23.** Published mechanisms below are **prior art**, not TAC-specific inventions, completed TAC experiments, or performance guarantees. Bibliographic links were checked against primary publication/publisher pages. No external trained code/weights were imported, no new study fitted, and no new real-world outcome was asserted by this literature review.

Each lane reuses established mathematics *only where it addresses a measured problem*, runs its **own** authentic original source/holdout protocol, preserves all trainable/deployed 95–105k future budget limits unless explicitly amended, and uses original model/checkpoint/replay receipts for each new fit.

## 1. System1: bounded continuous-time fast state and safe reflex inference

**Published prior work:** Hasani et al., [Closed-form continuous-time neural networks](https://www.nature.com/articles/s42256-022-00556-7), *Nature Machine Intelligence* **2022** (DOI 10.1038/s42256-022-00556-7). This work treats input-dependent continuous-time dynamics with a closed-form approximation; it provides mathematical inspiration for irregular sensor intervals, **not** proof of TAC sub-millisecond execution or authorized action gates.

**What to test on a newly qualified real reaction stream:**
- Forecast immediate observed hazard or state residual conditioned on the *last available tick*, in native fast state and delta-anchored forms, without oracle next-action fields.
- Measure true-action availability, missed-danger/false-action cost and initial response latency at p50/p95/p99 on named hardware, including preprocessing and any safety interface overhead. Loss of old-history context must be tested on real available histories.
- Compare practical persistence/simple control reference for deployment usefulness; only claim TAC architecture superiority with the separate equal-parameter/data/exposure/compute contract.
- **Fail** any assertion of reflex-policy safety without real signed authority receipts and prospective intervention outcomes.

## 2. Physical: known physical dynamics plus learned residual only where justified

**Published prior work:** [Learning dynamical systems from data: An introduction to physics-guided deep learning](https://pmc.ncbi.nlm.nih.gov/articles/PMC11228478/) (2024), describes residual/physics-guided modeling. For observed robotics a directly relevant hardware study is [Real-to-Sim: Predicting Residual Errors of Robotic Systems with Sparse Data using a Learning-Based Unscented Kalman Filter](https://ieeexplore.ieee.org/document/10202521) (2023; DOI 10.1109/UR57808.2023.10202521). These are general methods to *reuse*, not claims about ME06x trained models.

**What to test:**
- On actual timestamped original robot joint/sensor/action trajectories, FIT-identify the strongest real persistence or servo reference; do not assume servo is better. Stratify by genuine observed motion and contact **only if recorded**.
- A full 95–105k native TAC may learn bounded residual correction and a reliability fallback, trained on available historical source. Evaluate unexpected motion, long-horizon physical MAE/proper probability scores and failure after a shift at an original independently heldout real task. Compare original practical physics without neural parameter padding.
- **Fail** if residual makes an actual physical forecast worse or if a supposed contact flag comes from hindsight/fabricated labels. Do not retitle ME064/066 physical-persistence losses as success.

## 3. Enterprise: marked point processes, event-time likelihood and history-aware branches

**Published prior work:** Shchur, Biloš and Günnemann, [Intensity-Free Learning of Temporal Point Processes](https://openreview.net/pdf?id=HygOjhEYDH), **ICLR 2020**, establishes direct time-distribution modeling including mixture models rather than requiring an intensity-based point process. ME072's zero/positive clock is an applied design in that family; citing it is not a novelty claim.

**What to test:**
- One integrated native workflow model addressing real rare/early categorical branching, and training/scoring both true multi-horizon activity and waiting-time uncertainty from *actual original known-at-time prefixes*.
- Evaluate on original independent real institution/source cohort, class-specific errors and proper mark/time likelihood, Brier, calibration, coverage and p50/p90/p99 tail widths for every registered horizon.
- Source-log ending EOR is only a retrospective suffix proxy. No actual enterprise completion, SLA breach, risk/revenue saving or causal action outcome claim unless verified labels and measured costs truly exist.
- **Fail** on early 2-event equivalent knowledge if worse than FIT-only multi-event process baselines; do not hide regressions behind six-observation or aggregate headline scores.

## 4. Temporal: valid-time / transaction-time bitemporal audit with model input correctness

**Published synthesis:** [Comprehensive insights into bitemporal databases: a PRISMA-guided systematic literature review](https://link.springer.com/article/10.1007/s42488-026-00162-x), **2026**, records the established valid-time vs transaction-time distinction. Bitemporal data modeling and rollback semantics are prior database research—not a newly discovered neural capability.

**What to test:**
- First software correctness: reconstruct state exactly at each requested valid-at + **known-at** cut with authentic ordered/backdated/altered records, and prove later-known corrections do not leak into earlier as-known-at predictions.
- Then on a *real authorized corrected enterprise history* compare full native forecasting with/without accurate historically reconstructed input when target outcomes are later independently verifiable, while preserving original source truth in Woyengi.
- Quantify reconstruction source availability, unknown/conflicting revisions, late-event errors and real predictive quality; never assert compliance/legal proof from correct code-only reconstruction.
- Deterministic replay may be O(history); do not promise efficient logarithmic rewind trees without implementing and measuring them.

## 5. Edge-Lite: hardware-aware deployment and honest model-accuracy accounting

**Published prior work:** Lin et al., [MCUNet: Tiny Deep Learning on IoT Devices](https://papers.neurips.cc/paper_files/paper/2020/hash/86c51678350f656dcc7f490a43946ee5-Abstract.html), **NeurIPS 2020**, jointly optimizes network architecture and microcontroller execution engine, with measured device/memory outcomes. Its performance numbers cannot be copied to TAC-OSM.

**What to test:**
- Pin and verify an **original trained 95–105k learned-parameter model**, export candidate to INT8/FP16 with signed and compatible deployment metadata; compare real heldout prediction/interval scores **before and after quantization** and check numerical operator support.
- Benchmark named real edge hardware under representative batch=1 streams: p50/p95/p99 latency, peak RAM/flash, power/energy, cold-start and error response; report real price/device setup.
- Neither low byte size nor counting only actively nonzero weights changes the prospective **deployed learned parameter** rule. Training a new 10–15k model requires a documented owner policy amendment before fitting. No premature '<50ms' or sub-ms guarantee.

## 6. Counterfactual: real action-support, off-policy evaluation and credible identification

**Published prior work:** Dudík, Langford and Li, [Doubly Robust Policy Evaluation and Learning](https://icml.cc/2011/papers/554_icmlpaper.pdf), **ICML 2011**, develops off-policy evaluation for contextual bandits. Jiang and Li, [Doubly Robust Off-policy Value Evaluation for Reinforcement Learning](https://proceedings.mlr.press/v48/jiang16.html), **ICML 2016**, extend that problem to sequential decision-making. Both methods require careful support/behavior-policy assumptions; they do **not** grant causal validity to unlabeled loan process logs or synthetic Veritas outcomes.

**What to test:**
- Obtain original real action availability, logged behavior-policy propensities, verified action/outcome timing and costs. Assess factual conditional state predictions before counterfactual benefits.
- If identification/overlap is defensible, preregister honest IPS/DR or other appropriate sequential policy evaluation with effective sample sizes, uncertainty, support diagnostics, real no-action reference and an independently heldout policy cohort.
- Veritas/MCTS simulated branches only support *internal stress tests*. Authority remains outside TAC; no live robot/enterprise action selection, monetary gain or true `do(a)` improvement until an approved prospective independent field study.
- **Fail** if propensity/overlap or observed alternatives are unavailable; return uncertainty and reject causal claims rather than inventing treatment-effect supervision.

## Cross-lane research process: stop rediscovering known methods

- **Select the source/ability first:** real, licensed, timestamped original entity histories and genuine at-time-known inputs, relevant outcomes and correct denominator. No synthetic headline claims.
- **Select established mathematical basis second:** prioritize prior art above, then add only scientifically motivated TAC-specific state/retention/interaction structures. Store the original method citation and distinct novel hypothesis explicitly.
- **Train third under active guards:** new actual model/checkpoint must obey the binding trained/deployed learned parameter gate, record every arm/seed/optimizer update, preserve original in-repository checkpoint bytes and independent real score replay.
- **Prove capability, not ego:** report what new end-to-end skill is learned and whether it helps authentic factual predictions, including all negative slices and tails. When no comparably scored prior capability exists, report *new skill on real DEV* rather than a fake improvement. Independent gain on genuinely unseen real outcomes requires the canonical preregistered threshold/paired case confidence criteria. Commercial benefit requires outside customer evidence.
- **No automated data-source/license assumption:** published paper benchmarks and GitHub code are not rights to train on private Woyengi, customers' loan histories or Veritas scenarios as operational outcomes.
