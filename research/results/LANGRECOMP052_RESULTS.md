## Resource accounting and statistical boundaries

3,904B is the original *retained state tensor* allocation of incremental streaming. It is already approximately **0.0039MB** decimal. The raw byte buffer of 144B or528B retained after recomputation is **not an alternative full model process memory count**: model parameters, optimizer/checkpoint deserialization, Python and PyTorch allocator, temporary full token input tensors, large transient activations during full-prefix `prefill`, runtime/CPU heap, and GPU VRAM are excluded. Inference state recomputation may actually **increase peak transient memory** while reducing tensors saved between decoding calls; this experiment does not measure those peaks.

Do NOT present saved retained state as a 99% GPU VRAM saving. User-provided GRAPH011 5.51 MB→0.0014 MB figures were not source-traced to a verified actual method and are not replayed here. Training activation checkpointing is a separate computation: to qualify, run genuine original source forward+backward with and without checkpointing at equal graph/inputs/precision, compare losses, gradients and optimizer states before updates, and measure `torch.cuda.max_memory_allocated()` and `max_memory_reserved()` after proper synchronization with an explicitly authorized genuine dual NVIDIA T4 path. Record weights, gradients, optimizer and saved activations separately; original checkpoint size on disk is also a different quantity. This is **NOT_RUN** without separately approved GPU compute.

## Research decision

**Do not integrate full-prefix recomputation into streaming TAC inference as an unconditional optimization.** It sheds tiny retained tensor cache at much higher CPU cost, while the existing native state is already only3904B. Preserve as a causal numerical baseline. For phone-first TAC language, target source-key survival and selective computation first; if training memory truly bottlenecks future model scaling, implement proper segment activation checkpointing or recomputation at the training graph and prove gradients; verify actual GPU memory rather than extrapolating from a toy byte estimate.

The separate LANGMEMORY051 key-residency original-source finding remains authoritative on its own domain (lost source keys); the GPU/training recomputation question is orthogonal.
