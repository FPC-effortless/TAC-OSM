## Scientific interpretation: strong mechanistic clue, not a validated model improvement

The original `ContextTransition026` `phi_position` uses log/trigonometric absolute position features. For reset windows of length256, absolute positions128..255 are beyond the 128-byte fitted input context. An inference-only `controlled_position(model,"cap_all")` PyTorch forward prehook maps positions beyond127 to exact original 127 reference coordinates; all other logits are computed by the unchanged trained neural weights, upper recurrence and source inputs. The source L128 negative control passes exactly. This differential strongly implicates **untrained absolute positional extrapolation as a major contributor** to native L256 degradation in this reset-window cohort, without isolating the rest of the state/memory or guaranteeing long-horizon retention.

The result is **posthoc exploratory on previously exposed DEV**, not fresh external original source or protected TEST, independent generalization, full recurrent streaming, original checkpoint promotion, new trained architecture, a model-scale universal law, verified on-device Android efficiency or SSM/GRU/Transformer superiority. The L256 evaluations **reset** history before each target and the models had been trained on 128, so they do not test carried persistent memory. Exact full PyTorch original-source IEEE/AD/formal proof and all PNDS variant registry obligations remain OPEN; PNDS [#70](https://github.com/FPC-effortless/pnds-lean/pull/70) provides only partial cap integer law and [#71](https://github.com/FPC-effortless/pnds-lean/pull/71) partial FFN parameter-count arithmetic.
