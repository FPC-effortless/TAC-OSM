Historical source exact-match reference predicts earlier **observed** continuation byte raw[a] not guaranteed current future source byte raw[t+1], so accuracy below100% is expected for repeated phrases with different continuations. Learned writer "highest cosine context-match" is not a learned byte-decode classifier accuracy. It measures original trained key ADDRESS RANK against ground-truth matched preceding observed contexts, **conditioned on a matching candidate existing**. Outside that subset, the source query cannot select a correct historical match from that bounded window, regardless of numerical key competence.

**Critical explanation of the striking L=4 result:** The actual original native key `native_key(tanh(local))` depends on *current source lexical byte plus three previous lexical embeddings*, with shared parameters across positions and no explicit time index directly in native address. A repeated exactly four-observed-byte context therefore generates identical normalized learned native address `q_t` and historical `w_(a-1)` up to floating-point numerical precision, structurally. Hence exact-matching four-byte-context keys winning **100% conditional top1** is not evidence the model *learned* robust historical semantics or could decode the actual source past continuation from its bounded 8×8 matrix. Future labels are absent from the writer selector, but equality is essentially built into the deterministic key mapping. At L=2/3 partial keys can match without the full previous3 lexical context, so top1 specificity degrades. This is a causal source-key geometry finding, not a long-memory content recovery victory.

**Side-table byte selection with larger history:** At H256, original trained learned highest-cosine writer's historical byte happens to equal true source raw[t+1] on **27.2135% of the 768 observed next-byte labels** (this is same selected writer for each L, since q_t and H don't depend on L). Random original past writer continuation accuracy **3.5156%** in L2/H256 cohort; exact-history latest correct continuation **74.6269% only when a 4-byte match exists**, but that match coverage is **17.4479%**, and it uses an extra plaintext history table. The original genuine pretrained dual model itself has source NLL mean **2.12022195** over 768 actual source clocks. Frozen exact-history Dirichlet tau=8 continuation distribution with L2/H256 has NLL **4.66665628** averaged over all clocks (it defaults near-uniform when context absent). Therefore **standalone raw exact history counter is substantially WORSE than the neural model across all clocks**; no new language quality win. Context and byte comparisons are measured on already exposed publisher DEV and are not independent competitive benchmarks; no parity-matched SSM/Transformer is used here.

## What the research answers and what remains

LANGMEM080 showed old slow latent writes survive (17.6% after 128 genuine observed bytes) but produce tiny next-byte effect, while key cosine decays over longer delays. LANGMEM081 establishes that source's four-byte deterministic native address *can identify exact repeated four-byte contexts from an explicit table of past keys*. The failure is **not necessarily inability to generate matching raw-context addresses**. Remaining problems: (1) repeated correct four-byte contexts often do not exist within 256 observed historical bytes; (2) the same context can have different past continuation values; (3) stored native matrix superposes writes/erasure and does not provide indexed past event access or calibrated source-byte reconstruction; (4) unbounded side-table source-history oracle is NOT the model's actual fixed-memory mechanism; (5) the old trained 078 slow lane lost 0/3 source streaming next-byte comparisons to fast-only original 070 despite context-key consistency.

**Next scoped research gate:** source-grounded **value recoverability from the actual compressed slow 8×8 state**, with correct past-source history content known only to the evaluator, wrong-content/label-blind controls and explicit low-dimensional information-capacity pressure. Try a bounded indexed raw-history ring or source-tagged recent cache as an external edge storage competitor, and measure actual total persistent bytes/CPU read cost; do NOT replace the existing model by a full plaintext oracle while claiming the same 4160B memory. For trained neural retrieval, next develop a model that learns **which old continuation to write, when to query it, and how to decode the retrieved value**, with longer true-source FIT sequences and **new independently registered licensed unseen DEV**. Match architecture training FLOPs/model params/dataset exposure before claiming superiority.
