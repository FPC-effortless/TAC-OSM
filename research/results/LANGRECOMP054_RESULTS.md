## What these numbers prove and do NOT prove

The software checkpoint mechanism **empirically preserves output and all original 499623 gradient elements** under original FP32/source/RNG for both tested short windows, including native 8×8 associative, two aligned heads, wave, persistent concept evidence and upper recurrence with no omitted trained weights. Logical forward autograd saved-tensor requests for full checkpointing drop~98%; this supports exploring training-memory rematerialization and unlike original LANGRECOMP052 inference per-token prefix-replay it has a quantifiable CPU work/activation-saving trade-off.

However: `saved_tensors_hooks` counts sum of **logical request bytes**, including alias views and repeated save requests; it does NOT measure unique live tensors, CPU peak RSS, peak GPU allocated/reserved VRAM, total checkpoint disk bytes or actual acceleration device memory use. Weight storage ~1,998,492B FP32, gradients, optimizer, CUDA context, all transient tensors during recomputation, host allocator and runtime are not part of this request count. The original user-provided GRAPH011 5.51MB→0.0014MB, 99% VRAM remains **UNVERIFIED**; no original GRAPH011 implementation located or imported. Real GPU requires explicit trusted physical dual-T4 proof/approval, no promise of 99%, and proper synchronized `torch.cuda.max_memory_allocated()/reserved()` including weights and optimizer. We did **not** use GPU quota or open TEST.

Both first 053 and warmed 054 original evidence retained. The full graph workaround is currently a training-memory research branch, not automatically deployed to mobile inference; original 3904B persistent inference state remains efficient, and original LANGMEMORY051 key-residency bottleneck remains uncorrected. The train-time memory/time study alone does not show improved language NLL/accuracy, novel architecture moat or generalization. Source-level full model typed PNDS Lean/Python correspondence/finite-precision/AD proof remains OPEN.

**Decision:** Keep native streaming inference. For constrained *training* memory, prefer full-graph rematerialization candidate over upper-only on current logical request-byte metric if its increased CPU compute is affordable. Before deployment or GPU optimization claims, independently replay a genuine original source and checkpoint segment-level checkpointing variant, matched gradient and optimizer update, and actually measure peak GPU memory. Leave PR draft and all original trained checkpoints unchanged.
