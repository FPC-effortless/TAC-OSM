## Matched benchmark and limitations

Unchanged `DeepCacheTAC104` from the LANGDEPTH106 four-layer configuration (998,024 parameters; width120, FFN224, heads4, W128, C32) versus unchanged `CausalTransformer107` (998,816 parameters, four layers, width128, eight heads, context128). Same GitHub-hosted CPU runner, PyTorch, two CPU threads, deterministic synthetic byte-token timing fixtures. There were **no loaded trained weights**, no authentic corpus, no TEST scores and no GPU runs; these are *execution-path benchmarks*, not quality or general efficiency results. Wall times are ordinary *uninstrumented* process timings with separate warmups and repeated measurements.

| Operation | TAC median | Transformer median | TAC / Transformer |
| --- | ---: | ---: | ---: |
| Inference-mode prefill, B8 × T128 | 66.775730 ms | 28.568399 ms | 2.3374× |
| 16 incremental decode updates after 128-byte prefix, B1 | 75.121152 ms | 25.307317 ms | 2.9684× |
| Decode per generated byte | 4.695072 ms | 1.581707 ms | 2.9684× |
| Actual full AdamW optimization update (B8 × T128, cross-entropy + backward + AdamW step) | 170.003815 ms | 81.998814 ms | 2.0732× |

Decoder throughput: TAC **212.99 bytes/s**, Transformer **632.23 bytes/s**. Persistent tensor state at 128-byte prefix: TAC **295,936 bytes**, Transformer **524,288 bytes**. These model states exclude model weights, runtime metadata and transient activations.

For TAC prefill, the largest **self CPU operator** groups are `aten::mm` (12.593 ms, 53 calls), `aten::mul` (6.652 ms, 722 calls), `aten::cat` (3.428 ms, 340 calls), `aten::tanh` (2.553 ms), and CPU Flash SDPA (2.506 ms, **16** calls).

For TAC single-byte decode, the profile records 81 `aten::linear` calls, 178 `aten::mul`, 102 `aten::_to_copy`, 523 `aten::as_strided`, and **28** `aten::all` (state validation) calls. The Transformer uses 17 `aten::linear`, 48 `aten::mul`, 16 `aten::addmm`, and 195 `aten::as_strided` in its one-byte profile. These counts reflect the *current implementations*, not minimal mathematical requirements.

The local attention implementation issues **16** CPU Flash SDPA calls during batch-8 prefill (four 32-token tiles per layer × four layers), whereas the Transformer uses **4** (one per layer). Unlike the older attention-free/bounded-memory design, the modern TAC now incurs local attention and both associative banks each layer.

## Conclusions and experimental prioritization

1. The regression is real for the measured two-thread CPU source path: TAC takes roughly 2–3× the Transformer latency in prefill, decoding and a training update. These data do not imply GPU or long-context inferiority.
2. **The fast/slow bank pair is a first-priority prefill target**, followed by the rotary scan and tiling/attention implementation. A single knob cannot be assigned the total measured slowdown without a counterfactual ablation.
3. **For batch-one decode, operation fragmentation and validation are major targets.** The repeated tiny projections, casts and 28 finite-state checks per step are plausible candidates for prevalidated trusted-state execution and kernel fusion. A GPU sync claim requires an actual GPU benchmark.
4. The modern model uses **295,936 bytes** state versus the Transformer’s **524,288**, a 43.6% reduction at this fixed length. This is substantially less dramatic than the earlier 3,904-byte TAC recurrent-state footprint; model configurations and capacities differ.
5. Follow-up `LANGEFF109` should implement tested no-change-to-logits optimizations: validation-outside-hot-loop on trusted state, coalesced fast/slow bank projections, a reduced-local-attention launch path, fused rotary scan, and an optimized compiler/kernels lane. Evaluate these against the same reference, with numeric state/logit equivalence and held-out quality unaffected.

**Do not** use profiler-inclusive labels as exact percentages of wall time, assume random-weight performance measures learned capability, or assert GPU gains from this CPU-only study.
